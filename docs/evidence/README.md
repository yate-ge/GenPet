## 2026-10-03 0.9.1 可见状态变体与评审问题的提示词修正

依据五组周期评审（故事趋同、阶段与特殊形态变化弱、事实越界、状态变化没有体现在形象上）。

- 状态包括看得见的样子：穿着打扮、饰品、手持、携带或使用的物件、坐具、姿态。故事让它变化时，Avatar 生成或复用状态变体（同一身体，只改穿戴等），保存在这只宠物名下，回到旧状态时复用；纯内在状态和琐碎变化不重画。evolution 新增 `visibleState`，appearance 据此判断。引擎本来就允许不换阶段的形象更新，新增测试覆盖变体与复用。
- meta.md：不必每篇以用户行为开头；避免相同收尾主题；特殊形态起因可来自宠物自己的经历；各阶段之间要有看得见的差别，特殊形态不是调色；不扩写用户事实的时长、次数、动作与对话。story/output 检查点同步，输出只使用已接受的图。

## 2026-10-03 Dots 分离方案走不通：改为 Codex 本地安装，Dots 通过切换使用

在 Dots 里按“Codex 与 Dots 分离”的思路实测 0.8.0/0.8.1：

- 程序能运行，`status` 通过；蛋图集（9 组动作、16 个方向、73 帧）做出来了，但**无法创建或替换 Dots 的 pet**。Dots 按 Codex pet 制作技能验收：打招呼必须有附肢挥动，完整无肢的蛋过不了；转向姿态也有约 22 像素的位置跳动。因此故事无法提交（现有流程要求头像绑定成功），定时更新也没开启。
- 云端插件目录只读、搜不到 GenPet，无法从 GitHub 导入；只能把仓库下载到可写目录运行，每次都要用户确认。
- 把同一套蛋素材用到 Codex 桌面 pet 时，Dots 的电脑控制工具禁止操作 Codex 应用，没法安装或选中；这是 Dots 的权限限制，不是 GenPet 或素材的问题。仓库里的 `publish` 与 `switch-pet` 脚本本身可用，Dots 读过代码但没有执行。

**决定（待开发）：** 用户在本地 Codex 里安装并运行 GenPet（桌面 pet 为主，故事、形象更新和定时任务都在 Codex 里完成）。使用 Dots 的用户，把 Codex 里做好的 pet 切换到 Dots 上使用，不再让 Dots 独立生成和更新形象。蛋保持完整常规蛋，不为 Dots 的校验加附肢。

**开发时要先弄清：**
1. Codex 做好的 pet 怎样出现在 Dots 里（账号同步，还是手动导入），Dots 里能否自动选中。
2. `genpet-dots` 包怎么办：保留为只负责故事推送、不更新形象，还是删除，由 Codex 包覆盖全部。
3. 故事、定时任务、Dots 主动行为在“Codex 运行、Dots 使用”的模式下各自由谁触发、在哪里展示。
4. 引擎里 Dots 专用的 `avatar` 格式、`bind-avatar`、`host-request` 是否随之下线；以及“头像暂时换不上时故事仍能完成”的降级路径是否还需要。
