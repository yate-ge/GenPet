# 生成单元证据摘要

0.5.0 开发中生成单元测试的简短结论。原始报告、请求、结果和图像保存在本地 `output/`（不纳入版本控制），路径列在每节末尾，用于有本地副本时追溯。所有样本使用虚构上下文，不是真实领养；少量样本不代表成功率，也不替代用户对意义、形象与宿主显示的判断。

状态含义：

- **当前**：在现行规则下有效，可作为后续工作的依据。
- **暂停**：现行规则下的当前轮次，结论未完成或已被用户反馈推翻。
- **中止**：规则变更前开始的轮次，局部观察保留，不作为当前接受。
- **撤回**：在错误的产品边界下得出的接受结论已撤回，图像只作负例。

## 故事依据静态复测

2026-10-02。A 蛋 v1、B 幼年 v2 是当前正例，其余候选撤回。

- 固定虚构 context 与 encounter：保留写作片段的界面，蛋在会重新打开的窗沿获得。三份设计是 A 归衔（燕子）、B 展鹤（折纸鹤）、C 启蚌（蚌，无五官）。
- **用户接受 A 蛋 v1**：完整常规卵形蛋，个体线索在壳面斑纹。
- **用户接受 B 幼年 v2**：卡通像素、幼态，小尖喙、短弯颈和三角折翼保留来源。独立检查也判 accept。
- **撤回**：B v1 过于写实，看不出幼年。C v1 缩小后读作肉质的蚌，不可爱，违反同伴边界，只作负例。
- 规则已据此写入 `framework/prompts/meta.md`：卡通像素、幼态、可爱同伴、联系不限于工作。
- 这一轮的测试流程与运行时不一致：使用手写图像请求，没有经过 `prepare_pet_run.py`。记录也偏重。这些都已在 `generation-units.md` 修正。
- 测试 case 过度约束：虚构资料只围绕工作，encounter 由测试作者撰写，C 被 fixture 强制无五官。现在 fixture 只提供原始资料，上游内容由 Agent 生成。
- 未生成动画，未安装，也未操作真实 Pet、Avatar 或调度。
