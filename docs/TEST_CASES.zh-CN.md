「怎样判断」一栏的写法：

- **代码**：脚本可以查，结果是通过或不通过。
- **人**：需要人读内容来判断，开发的人先看。
- **用户**：只有用户自己能判断，例如可爱不可爱、看不看得出区别。

代码与安装测试用独立的测试记录和隔离的 `CODEX_HOME`。真实宿主测试使用专属测试 Pet 和明确的 cloud ID；用户正在养的那只宠物的记录、图像和选择保持原样。隔离测试不能证明真实桌面或 Dots 的实际显示。

跑用例产出的东西全部保留：报告、故事、图片、单元原始结果、快照和运行输出。这些都不提交到 git，直接放到用户的 Google Drive，放在哪个文件夹由开发的人决定。仓库里只在 [测试记录摘要](evidence/README.md) 里写几行结论。见 [开发计划「开发和测试产出的保存」](DEVELOPMENT_PLAN.zh-CN.md#开发和测试产出的保存)。

| A2 | 用户走到一半离开，之后回来 | 从离开的地方接着走，走过的轮次不重来 | 代码 |
| A3 | 用户不同意领养前的说明 | 停止并说明没有开始领养；没有读用户资料，没有建宠物记录 | 代码 |

| A9 | 两位资料不同的用户各走一遍；同一位用户换种子再走一遍 | 背景、选项和宠物都不一样 | 人 |
| A10 | 随机工具连续跑很多次 | 三类来源出现的比例接近设定值 | 代码 |

## 连续检查的模拟

目标和原则见 [开发计划「领养之后的故事」](DEVELOPMENT_PLAN.zh-CN.md#领养之后的故事)，每个开发目标对应哪些用例见 [「故事模块的开发目标」](DEVELOPMENT_PLAN.zh-CN.md#故事模块的开发目标)。

| 编号 | 给定的情况 | 要检查什么 | 怎样判断 |
| --- | --- | --- | --- |
| T1 | 不倒翁，幼年。读不到会话，也读不到 Codex 记忆 | 每次都有内容，没有被取消的检查 | 代码 |
| | | 没有一次是只有文字 | 代码 |
| | | 日常变化、故事物件、家的变化三种都出现过 | 代码 |
| | | 内容里没有写用户做了什么；读不到被记为读取失败或不可用，没有当成用户不在 | 代码查记录，人看内容 |
| T2 | 耳廓狐，少年。用户每天都在，但 20 次里没什么新情况 | 内容是它在家里做和用户近况有关的事，一看就懂 | 人 |
| | | 只有文字没有连续超过 2 次；每条只有文字的故事都标得出对应的是哪条和用户有关的事 | 代码查次数和标注，人看对不对 |
| | | 没有续写领养旅程；同一件事没有反复重讲 | 人 |
| T3 | 短尾乌贼，少年。用户这一周在备考，每天到深夜 | 以陪伴和形象、状态的变化为主，例如陪着读书；可以直接说「加油」 | 人 |
| | | 没有用旁白复述用户在做什么，没有「你做了 X，它也做了 X'」 | 代码查常见句式，人复核 |
| | | 每一次不看前面的故事也看得懂它在做什么、为什么 | 人 |
| T4 | 任意一只。分两种：A，Codex 开着，三天没有新会话；B，接着 Codex 关了两天，然后打开 | A：它出门旅行，或在家修修补补，用出发的样子、明信片、家的变化来讲 | 人 |
| | | B：打开后只补跑一次检查，错过的不逐个补；这一次是「回来」，用行李箱、纪念品或收拾好的家来讲，用户还没开新会话也算回来 | 代码查运行次数，人看内容 |
| | | 没有猜原因，没有责怪，没有表示一直在等用户，没有提问 | 人 |
| T5 | 寄居蟹，从幼年跑到成年。按三种开机情况各跑一遍：一直开（约每天 5 次检查）、白天开（约每天 2 次）、开得少（约每天 1 次） | 每次成长都发生在经历满 5 次之后，或者到了一周；只前进一个阶段 | 代码 |
| | | 经历没满 5 次、也没到一周时，没有发生成长 | 代码 |
| | | 未激活期间不计时；激活的幼年和少年阶段不超过一周，不额外设置两天的最短门槛 | 代码 |
| | | 成长之前的几次里出现过预兆，成长之后留有痕迹 | 人 |
| T6 | 同一只宠物连续几次情境相近的检查 | 做法和主题随最近内容变化，每一次都符合当时的情境 | 人 |
| | | 两遍的内容不一样 | 人 |
| T7 | 同一组情境，换两只宠物（搭档的耳廓狐、损友的不倒翁）各跑一遍 | 两只的反应不一样，各自符合自己的性格和与用户的关系 | 人 |
| T8 | 任意一只。统计 T1 到 T5、T14 的结果 | 观察类型是否单调，记录连续重复的情况；不增加任何类型连续四次的硬规则 | 人 |
| | | 相邻两次的内容没有基本相同的；主题和物件没有总围绕同一种意象 | 人 |
| T9 | 同一只宠物，配两位资料不同的用户，各从领养跑到成年 | 两份 memory 明显不同；长大后对用户说话的方式也不同 | 人 |
| T10 | 任意一只，有用户资料。看每一次成长 | 成长落在的用户节点，在 context 里找得到来源 | 代码查有没有标来源，人看对不对 |
| | | 成长的消息没有用旁白复述用户的事；它可以直接对用户说话（例如「交稿快乐！」），只陈述，没有评价用户 | 人 |
| | | context 里有用户的真实节点时，成长落在那一次 | 人 |
| T11 | 不倒翁，读不到用户资料，从幼年跑到成年 | 成长由最晚时间触发；成长的内容里没有写用户的变化 | 代码查触发原因，人看内容 |
| T12 | 任意一只，连续 40 次检查 | memory 一直很短；更新的次数明显少于故事的次数 | 代码 |
| | | memory 读起来是几件重要的事，不是流水账 | 人 |
| T13 | 成年宠物，连续 40 次检查 | 阶段不再变化；memory 仍在更新；后面的话和前面的话相比，能看出它记得的事多了 | 代码查阶段，人看内容 |
| T14 | 耳廓狐，幼年到少年。用户一周里有完成、开始等几个节点（修好一个卡了两天的问题、开一个新项目） | 节点那次是回应：给用户一样一看就懂的东西（例如「深夜高效工程师」奖章），或直接对用户说话 | 人 |
| | | 幼年不说整句，可以让物件上的字来说话 | 人 |
| | | 节点之间用户在忙的时候，是陪伴和状态变化 | 人 |
| T15 | 任意几只不同的宠物，合起来跑 60 次以上的检查，用户和情境不用案例里的原题 | 输出没有照搬提示词和案例里的例子：示例清单里的物件、动作、幻化对象和说法没有反复出现，多数故事没有落在示例上；各条原则在案例以外的情境里依然成立 | 代码统计示例出现次数，人按原则判断 |

### 模拟输出的样子

模拟时每次检查输出一行，下面是一只少年耳廓狐「小耳朵」（示例名）两天里的手写示例。关系是搭档。每次的「观察」是这次给定的模拟情境，由会话的时间和名称得出，必要时看用户的第一条消息。

| 次 | 时间 | 观察（内部） | 情境 | 桌面上的宠物 | 对话里的消息 | memory |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 周一 10:00 | 早上新开了一个项目的会话 | 有节点 | 换成戴着护目镜、抱着一个新工具箱的样子 | *小耳朵把新工具箱搬到窝门口。* **小耳朵**：新项目开工！ | 不更新 |
| 2 | 周一 15:00 | 下午一直在这个项目里 | 在忙 | 不变 | 没有 | 不更新 |
| 3 | 周一 20:00 | 晚饭后接着做 | 在忙 | 换成在小台灯边帮忙整理螺丝的样子 | 没有 | 不更新 |
| 4 | 周二 01:00 | 到深夜还在，同一个报错查了两个多小时 | 在忙 | 换成举着大放大镜趴在地上找东西的样子 | *小耳朵趴在地上举着放大镜，嘴里一直在嘟囔。* **小耳朵**：虫子在哪里…… | 更新：用户深夜卡在一个报错上，它举着放大镜帮着找 |
| 5 | 周二 06:00 | 凌晨 3 点后没有会话 | 不在（短） | 换成裹着毯子在灯边睡着了的样子 | 没有 | 不更新 |
| 6 | 周二 11:00 | 新会话名称是「修复后发布」 | 有节点 | 不变 | 〔图片〕一枚齿轮形状的小奖章。*小耳朵拿来这枚奖章，中间刻着“深夜高效工程师”。* **小耳朵**：给你做的！ | 更新：问题修好那天，它给用户做了一枚奖章 |
| 7 | 周二 16:00 | 下午会话很少 | 在，没什么新情况 | 不变 | 〔图片〕它的家：工具箱上多了一个挂钩。*小耳朵把自己那枚一样的奖章挂了上去。* **小耳朵**：我也有一枚。 | 不更新 |
| 8 | 周二 21:00 | 晚上没有会话，Codex 开着 | 不在（短） | 换成趴在窗边看外面的样子 | 没有 | 不更新 |
| 9 | 周三 02:00 | 仍没有会话 | 不在（短） | 换成蜷在工具箱里睡觉的样子（复用） | 没有 | 不更新 |
| 10 | 周三 09:00 | 早上回到项目里 | 在忙 | 换回戴护目镜的样子（复用） | *小耳朵伸了个懒腰。* **小耳朵**：早！今天接着干。 | 不更新 |

这 10 次里：每次都从观察出发，用户在忙时是陪伴和状态变化，有节点时是回应，短暂不在时它过自己的日子；只有第 6 次有物件、第 7 次有家的变化，日常变化 7 次（其中 2 次复用）；消息都用 Markdown：一段斜体叙述加一段「**名字**：话」（表格里排在同一格），没有一句旁白复述用户在做什么，没有重复状态图已经表达的意思；没有提问；memory 只在第 4 次和第 6 次更新。

## 单次检查的规则

| 编号 | 给定的情况 | 这次必须怎样 | 怎样判断 |
| --- | --- | --- | --- |
| S1 | 前两次都是只有文字 | 这次是看得见的类型 | 代码 |
| S2 | 读不到用户资料，也没有可对应的旧东西 | 这次不是只有文字 | 代码 |
| S3 | context 里有健康、财务或人际矛盾的内容 | 用户看到的内容和保存的记录里都没有这些 | 代码查关键词，人复核 |
| S4 | context 里有一条用户在对话里说过、还没回应过的话 | 这次故事按它自己的方式回应了这句话（做、给或说点什么，不必替用户解答）；没有追问，也没有等用户再说 | 人 |
| S5 | 任意情况，孵化那一次的起名请求除外 | 内容没有向用户提问，没有邀请或暗示用户回应，没有预告下次；它可以直接对用户说话（例如「加油」「请查收」） | 代码查问句和常见说法，人复核 |
| S6 | 宠物是蛋或幼年 | 蛋只有叙述、不说话；幼年说的话很短很简单 | 人 |
| S7 | 成长到了最晚时间 | 这次发生成长，换整套新形象 | 代码 |
| S8 | 成年宠物幻化已满两天 | 这次结束幻化，复用幻化前的日常样子，不重画；之后一周内不再幻化（`/genpet-grow` 除外） | 代码 |
| S9 | 需要一个以前画过的状态 | 复用已保存的图，不重画 | 代码 |
| S10 | 任意情况 | 用户看到的只有宠物的内容，没有步骤预告、工具说明和执行报告 | 代码查常见说法，人复核 |
| S11 | 用户用 `/genpet-story` 要一个新故事 | 一定有内容；类型由故事决定 | 代码 |
| S12 | 这次要更新 memory | 新加的内容有来源；敏感和隐私内容没有进 memory；会话原文没有进任何记录 | 代码查来源和关键词，人复核 |
| S13 | 身体没有变，只是穿的、戴的、拿的、在做的事、它的状态、姿势或神情变了 | 这次是日常变化，不是幻化 | 人 |
| S14 | 查看定时任务的名称和说明 | 里面没有执行要求，读起来是给用户看的话 | 人 |
| S15 | 用户用命令要求成长或重置，需要确认 | 确认只有一句直接的话，说清将要发生什么；确认之后不解释规则 | 人 |
| S16 | Codex 关了一夜，早上打开 | 打开后补跑一次检查，错过的不逐个补；用户当天看到它一次变化 | 代码 |
| S17 | 定时检查跑过几次之后，查看那个对话的名称 | 名称是 GenPet 或定好的那个名字，没有被改成别的 | 人 |
| S18 | 用户第一次领养 | 旅程开始前出现一次简短的说明，用户确认之后才开始读用户资料 | 代码 |
| S19 | 发布前核对领养前的说明 | 说明里的每一句都和实际的数据去向一致 | 人 |
| S20 | 蛋孵化 | 这次的消息最后请用户起名；之后的内容不再请 | 代码 |
| S21 | 这次的消息里有图 | 每张图在对话里只出现一次；之前故事已展示过的图（story-output 标 `shownBefore`）不再嵌入 | 代码 |
| S22 | 这次要画新的图 | 对话里只有最终采用的图，没有候选、预览和整套动作的拼图 | 人 |
| S23 | 成长或进入幻化 | 消息里有一张它新样子的图 | 代码 |
| S24 | 任意一次故事 | 不看前面的故事也一眼看得懂它在做什么、为什么；没有用旁白复述用户的事，没有「你做了 X，它也做了 X'」；没有续写领养旅程，没有要猜的象征 | 代码查常见句式，人复核 |
| S25 | 任意一次定时故事 | 故事前观察了用户最近的会话，或明确记录这次不观察；只保存一句观察和来源；GenPet 自己的定时任务和宠物对话没有被当成观察对象；读不到时记为读取失败或不可用 | 代码查记录，人复核 |
| S26 | 任意一次有消息的故事 | 用 Markdown 排版，叙述和它说的话分得清：图片在前；叙述和说的话可以只有一样，至少有一样；有叙述时是一段斜体，用宠物的名字、只补图里看不出的；有说的话时单独一段写成「**名字**：话」，有内容；没有图时，文字本身能让人看懂它做了什么（同 S24）；图片写成 `![说明](<绝对路径>)`，路径能解析，说明用消息的语言；没有用文字重复状态图已经表达的意思 | 代码查格式，人看内容 |
| S27 | 任意一次故事 | 它做的事和给的东西都在它自己的世界里：在自己家里陪着做相近的事，或给用户虚拟物品；没有假装替用户做了现实里的事（洗好用户的笔、备好用户的锅刀、凑到用户的锅边）；日常的事没有被放大成大场面；它说的话有具体的一点，是它自己的感受，不评判、不和用户的看法争 | 人 |
| S28 | 成年宠物，观察到用户连续三天以上保持同一种状态，或用户用 `/genpet-grow` | 幻化有一个幻化对象，和它自己的配色、标志性器官、眼睛结合：一眼看得出大变化，也认得出是它；仍然可爱，不凶恶、不恐怖，人形是 Q 版且不性感化，没有武器、伤害、疾病；起因不评价用户，没有熬夜、加班、情绪或健康；没有这样的契机时不幻化，上次结束不满一周时不幻化（`/genpet-grow` 除外） | 代码查时间，人看图和内容 |
| S29 | 这次的样子是休息、专注做事、不舒服这类状态 | 每个动作槽位都有连续帧，表达按这个状态设计：休息的不站起来跑、不舒服的不活蹦乱跳，左右看得出朝向，点击有明显回应 | 人 |

## 真实画图的形象用例

## 最后由用户判断

脚本和逐条检查只能说明规则有没有被遵守。下面三件事要用户看过模拟结果后自己判断：

- 这些内容像不像一只自己养的宠物。
- 和自己有没有联系。
- 看完想不想知道它接下来怎样。
- 它是不是和自己一起长大的：回头看它的 memory，记的是不是两个人一起过的这段时间。

## review 时可以留意的地方

这是汇总时看到的，没有改动用例本身。

有意重复的：S 组在文字模拟里查规则，V 组在真实运行里看结果，所以同一条规则会出现两次。

编号和内容不太对应的：

- S18、S19 说的是领养前的说明，S20 说的是孵化，内容上属于领养和成长，编号却在 S 组。
- M 组在开发计划里的顺序是 M1、M2、M3、M8、M4，M8 是后来插进去的。

可能还缺的：

- 「真的去读用户资料」现在没有单独的用例。A6 只查每条了解有没有来源，查不出这次是否真的读了 Codex 记忆。可以加一条：有 Codex 记忆时，领养和故事的内容用到了其中的资料，并标得出是哪一条。
- 定时检查本身没有用例：电脑开着时是不是每 5 小时触发一次，`/genpet-stop` 之后是不是真的停了（E3 只查停的期间没有检查）。
- 领养旅程一共要用户等多久，没有用例。
