# GenPet 设计

[English](DESIGN.md)

## 设计思路

**一只会和用户一起成长的虚拟宠物。** 现在的桌面宠物，包括 Codex 和其他 AI 客户端里的，形象都是固定的：每个人可以按自己的需要生成一只，生成之后就不再变了。GenPet 希望宠物和用户产生联系，会变化，会成长，成为一个能陪着用户、跟着用户一起变化的伙伴。它从一颗蛋开始：用户参与一段短短的奇遇，得到这颗蛋；蛋孵化成专为这位用户设计的小生命，慢慢长大。

**宠物观察用户，陪伴用户。** 宠物住在虚拟世界里。它观察用户，对用户的状态做出反应，和用户发生情感互动，让用户有陪伴感。它不需要用户来喂养和照顾。它在自己的小世界里有自己的生活，但首先是用户的宠物，陪伴用户是最重要的。

**身份一致，形象会变。** 宠物始终是同一个身份，同时可以成长。它通过观察到的上下文和用户建立情感联系，再据此改变自己的表达和形象。

**设计者定规则，生成式模型来生成。** 这个思路来自我们关于生成式智能体界面元设计的研究，发表为 [GenFaceUI（CHI '26）](https://arxiv.org/abs/2602.11055)。在那项研究里，设计者定义模板、规则以及情境怎样对应到表情，每个智能体的脸在运行时于规则之内生成，身份始终认得出，表情随情境变化。GenPet 用生成式模型的能力，让宠物成为一个动态的形象，同时守住两层一致：设计风格一致，宠物形象本身一致。变化都在这两层一致之内发生。产品规则定边界（字面的蛋、至少有眼睛的可爱像素伙伴、各阶段是同一只），Agent 在边界之内做所有创作，从宠物的设计到每一个故事。

**不只是宠物。** 同样的分工也适用于其他智能体和应用里的伙伴：产品规则定边界，Agent 做创作，少量代码保证身份和记录可靠。

## 故事

宠物通过故事和用户产生联系。每隔一段时间，它会生成一个新故事。

**故事原则**

1. **和用户有联系。** 每个故事都是对用户此刻的回应：用户忙的时候在一旁陪着，用户做完或卡住时说一句话，或者从它的世界里送用户一样小东西。用户一看就知道是冲着自己来的。
2. **为用户而写。** 故事的意义在于它和用户的联系，不为故事而故事。
3. **带来惊喜。** 每个故事都让用户觉得有意思，内容有来由，用户看得懂为什么会发生。

**每个故事一张图。** 图有三种：

| 种类 | 讲什么 |
| --- | --- |
| 场景图 | 宠物在某个场景里做某件事，也可以只画场景。宠物的家是场景图的一种。 |
| 形态变化 | 宠物的样子变了。日常样子：换穿戴、拿着的东西和在做的事，身体不变。成长：依次经过蛋、幼年、少年、成年。幻化：成年后少有的、临时的、好玩的变身。样子跟着宠物怎样回应用户而变（守着、庆祝、迎接）。 |
| 道具叙事 | 通过一样东西来讲：宠物带回家的，或送给用户的东西。 |

**长期运行。** 时间久了，宠物的家一直在变：添东西、整理、搬家。宠物积累起很多不同的形象，每一个都保留，以后可以再穿上。它带回来、送给用户、留在家里的东西都记下来，知道每一样来自哪个故事、现在在哪里。

## 原则

1. **用户的事不能编。** 宠物的世界可以虚构，用户的行为、情绪和话不能虚构。读用户资料前先征得同意，敏感内容不使用也不保存，只保存简短的观察和来源。
2. **规则定边界，Agent 来设计。** 每只宠物从一个具体、熟悉的来源设计（某个物种、某个传说、某部作品里的某个角色），每个主要特征都有理由。没有物种目录、身体模板或性格预设；随机只在有依据的设计之间做选择。
3. **一只宠物，一个身份。** 蛋是字面的蛋，只用壳面透露里面是什么。孵化后，每个阶段、每个新样子都认得出是同一只。soul、memory 和 state 保存在一起。
4. **先可爱、先看得清。** 宠物是可爱的卡通像素伙伴，至少有眼睛，在桌面的小尺寸下看得清。让人不舒服的设计不合格，故事再好也一样。
5. **弱打扰的陪伴。** 宠物观察、回应、陪着用户。它不提问、不邀请回复、不催促，也不让用户愧疚。成长不显示成次数、等级或进度条。
