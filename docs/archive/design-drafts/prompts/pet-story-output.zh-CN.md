# 宠物故事输出提示词草案

本文保留故事输出的设计依据；0.5.0 实际运行文件为 [output.md](../../../../framework/prompts/output.md)。适用于 Codex Dots 与普通 Pet，落实 [对话框输出要求](../../v0.5/PRODUCT_DESIGN.zh-CN.md)。

## 输入与职责

输入包括这只宠物的故事上下文、本次已经形成的新故事、实际完成的事件与状态、可呈现的故事图像，以及用户本次明确提出的请求。0.5.0 使用已保存的故事计划、素材与完成结果，具体入口见 [执行流程](../../../../framework/references/workflow.md)。

本提示词负责呈现用户看到的故事文本与图像。新故事先由 [故事任务](new-pet-story.zh-CN.md) 或相应事件机制形成，并决定状态与形象表达。资料依据、基因记录和执行记录由相应模块管理；素材生成与宿主更新由相应机制完成，不通过叙事冒充执行成功。

## 输出提示词

```text
这只宠物的故事上下文：
{{pet_story_context}}

本次已经形成的新宠物故事：
{{new_pet_story}}

当次实际完成的事件与当前状态：
{{completed_events_and_state}}

已经完成、能够向用户呈现的故事图像：
{{available_story_images}}

用户本次明确提出的请求：
{{user_request}}

在用户对话框中，只呈现当次宠物故事的文本与图像。让内容延续这只宠物的经历，与用户保持有意义的联系，同时表现它有自己的生活。

文本与图像共同表达当次内容。根据故事需要决定叙述视角、篇幅、图文组织和表达形式，保留此前示例之外的创作空间，不套用固定故事模板。

不要输出插件的运行过程、步骤预告、工具调用解释、执行日志、技术参数、基因设计说明或安装更新报告。不要在故事前后附加运行成功总结、工程说明或后续操作建议。对话中的文字属于宠物故事，图像属于当次故事表达。

以本次已经形成的新故事为内容依据，结合实际完成的更新、当前状态与可用素材完成图文表达。宠物的经历可以包含虚构情节，但尚未完成的形象更新、进化或状态变化不能被写成已经发生。只使用实际可呈现的图像，不以虚构的图片链接或完成声明代替素材。

用户通过命令明确要求与宠物对话时，在既定范围内以宠物内容回应，并继续遵守上述输出边界。
```

## 接入与验证

各项机制需要在内部完成必要记录后，将相关宠物内容交给这个输出任务。普通 Pet 与 Dots 分别使用自己的宿主接入；实际图像呈现与即时刷新留待对应环境验证。

调用失败、没有新增变化或故事素材未完成时，由 Agent 根据实际结果、当前宠物状态与可用素材自行组织内容。这些情况仍遵守故事输出边界，也不能伪造已完成的变化，不另设固定回复模板。
