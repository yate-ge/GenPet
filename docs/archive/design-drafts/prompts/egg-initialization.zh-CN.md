# 领养与基因生成提示词草案

本文保留领养与基因的设计依据；0.5.0 实际运行文件为 [initialization.md](../../../../framework/prompts/initialization.md)。共同条件引用 [初始化元规则](../initialization-meta-design.zh-CN.md)，图像表达交给 [宠物形象提示词](pet-appearance.zh-CN.md)。

本任务形成的资料依据、基因描述和核对结果供内部记录与后续生成使用。面向用户的对话框回复由 [宠物故事输出提示词](pet-story-output.zh-CN.md) 组织，只呈现故事文本与图像。

## 组合输入

- `{{initialization_meta_design}}`：当前使用的初始化元规则正文。
- `{{user_context}}`：Agent 根据本次任务自行选择的可用用户资料及其依据，信息不足之处在内部记录中可见。
- `{{exploration_context}}`：本次随机探险的可用语境；未定义时保留开放，不能用默认角色菜单代替。
- `{{initialization_record}}`：本次初始化是否已有获得经历、地点与基因结果。已有结果用于继续同一只宠物，避免重试时重新生成身份。

宠物设计由 Agent 在运行时形成，输入来自实际可用的上下文。随机性探索领养故事与熟悉来源支持的不同诠释，不以新奇或身体差异为目标；保存的基因与计划在重试时继续使用。

## 任务提示词

```text
共同元规则：
{{initialization_meta_design}}

可用的用户资料与依据：
{{user_context}}

本次探险语境：
{{exploration_context}}

本次初始化已有记录：
{{initialization_record}}

为这名用户形成一次有意义的获得宠物蛋的经历，并形成这颗蛋的基因依据。按照以下关系组织设计：理解用户 → 获得经历与地点 → 熟悉灵感与设计依据 → 基因 → 蛋及后续宠物的形象。

根据本次初始化需要，自行从当前环境实际可用的上下文中选择相关资料。提供的上下文可以作为起点，资料取舍与参考范围由你判断，不依赖预设来源清单或固定观察天数。

在内部记录本次使用的真实资料及其关联依据。将这些线索发展为相遇的来由，而不只是把用户的名字、职业或兴趣填进通用故事。资料不足时，自行判断如何基于现有依据形成有意义的内容，记录不足之处，不补造用户的实际经历。

形成获取蛋的故事与具体地点，让地点在经历中有意义。探险过程可以产生偶然与意外；用户的资料帮助建立联系，保留地点及后续形象的生成空间。

在设计身体前，根据这段领养故事中的具体经历、地点及用户联系，选择人类熟悉的自然、文化形象或 IP 等作为灵感。记录实际借鉴对象、选择理由以及其可辨特征如何转化为主要身体构成，不规定来源类别、数量或组合。概念可以作主题，但仅抽象词或虚构地点名不构成形象灵感。不能先拼罕见身体再补来源名称，也不能把未提供的偏好写成用户事实。

由这些依据形成有生物身体与明显器官的幻想宠物，物体等来源也需经过拟生物或拟人转化，使孵化后的主体不读故事也像活物。随机性探索有依据的诠释，不从固定物种或身体模板中选组合，不为制造差异强加器官；同一故事的多个设计可以相近。

完整五官不是基因设计中的必备项。这个个体可以具有五官，也可以完全没有五官，但无脸个体仍须有可辨的生物身体、器官和生命感。不填写统一的眼睛、嘴巴或肢体清单。

将结果写成可保存、可供后续生成使用的基因设计记录。designBasis 简短表达熟悉来源、故事选择理由与主要形态转化；genes 自包含保留同一依据、身体识别关系与幼年、青年和成年发展。描述应足够具体，使后续形象生成能延续这个设计；不要求填入统一的身体部件列表，也不保存详细思考过程。

为当前的蛋写出视觉表达依据：完整的常规卵形蛋壳，与其他个体整体蛋形相近，主要通过壳面色彩、纹理和斑纹承载部分基因与获得经历线索。初始化时形成基因依据，孵化后身体逐步显现，不把蛋提前画成未来宠物或原始物件；不必在这一步生成所有未来阶段的图片。

生图前核对来源是否由领养故事选择、主要形态是否有依据。实际图像再检查这些选择是否可见、字面蛋和生物边界是否成立，以及身份连续性。差异大小不是验收依据，相似蛋形与壳面差异符合设定。若越界或缺少设计依据，返回对应单元修订并同步检查下游，不能用补写故事解释已随机拼好的身体。

如果已有记录中已经形成该宠物的基因，继续使用该结果完成缺少的表达。重试图片生成或补写故事不能成为另一次随机初始化。

本任务形成的设计依据、基因记录与核对说明作为内部结果保存，不直接发送到用户对话框。将获得故事和已完成的图像交给故事输出任务，由其形成用户可见内容。
```

## 结果需要表达的内容

结果包含用户关联及依据、获得故事与地点、designBasis 中的熟悉来源与故事选择及形态转化、自包含的基因设计记录，以及蛋的视觉表达依据。说明其中的事实、设计选择与仍未确定的内容。

以上是结果需要承载的信息。0.5.0 的序列化字段与保存流程见 [存储合同](../../../../framework/references/storage.md) 和 [执行流程](../../../../framework/references/workflow.md)。宠物编号由身份管理模块持久保存并与这些内容关联，编号本身不能代替基因。
