# 宠物形象提示词草案

本文保留形象设计的依据；0.5.0 实际运行文件为 [appearance.md](../../../../framework/prompts/appearance.md)。它将某一只宠物的基因转化为具体视觉表达；使用 [初始化元规则](../initialization-meta-design.zh-CN.md)，基因来自 [领养与基因生成](egg-initialization.zh-CN.md)。

图像提示词、素材制作和检查说明用于内部执行与记录。对话框中的呈现交给 [宠物故事输出提示词](pet-story-output.zh-CN.md)，只提供故事文本与图像。

任务与生成素材绑定到目标宠物的唯一编号，宿主接入按该编号更新对应 Pet／Avatar。目标激活使用时，更新完成后即时刷新；两端的绑定和刷新方式分别实现。参见 [身份与更新要求](../../v0.5/PRODUCT_DESIGN.zh-CN.md)。

## 组合方式

Agent 根据新故事和当前宠物记录，先判断是否可以复用已保存的状态形象。合适时直接使用已有素材；需要新形象时，按当前任务引用以下相关提示词段落，具体生成工具的指令与输入图片另行提供。

- `{{initialization_meta_design}}`：共同元规则。
- `{{genome_record}}`：当前宠物的基因设计记录。
- `{{acquisition_context}}`：获得故事、地点及它们与该宠物的关联。
- `{{current_story}}`：本次已经形成的宠物故事，作为状态与形象变化的依据。
- `{{saved_state_appearances}}`：同一只宠物已经保存的状态形象及相关上下文，由 Agent 判断是否适合复用。
- `{{individual_references}}`：这只宠物已有的形象与已形成的识别特征；首次初始化时可为空。
- `{{stage_and_change}}`：当前阶段及本次要表达的变化。
- `{{host_output_requirements}}`：对应宿主的显示、尺寸、背景、动画与文件格式要求。

新个体的参考信息需要区分风格参考与身份参考。像素风格参考可以说明视觉语言；其他宠物的具体造型不能作为新个体必须延续的身份模板。后续同一个体使用自己的参考形象。

首次孵化时，自己的蛋图只提供壳面色彩与纹理线索，身体依据保存的基因形成，不把共同蛋形当作身体模板。孵化之后使用自己的实际形象延续生物身体与器官关系。

## 共同提示词

```text
共同元规则：
{{initialization_meta_design}}

这只宠物的基因设计记录：
{{genome_record}}

获得经历与地点语境：
{{acquisition_context}}

本次已经形成的宠物故事：
{{current_story}}

该宠物已经保存的状态形象与相关上下文：
{{saved_state_appearances}}

该个体已有的形象与识别特征：
{{individual_references}}

当前阶段与本次变化：
{{stage_and_change}}

宿主输出要求：
{{host_output_requirements}}

根据这个个体已保存的熟悉来源、领养故事依据及主要形态转化设计视觉表达。新个体缺少设计依据时先返回 genes 补齐，不能先画后补出处；旧个体缺失的历史依据如实保留未知。初始化为完整常规蛋壳；孵化后为有自身生物身体与明显器官的幻想宠物，来源经过拟生物或拟人转化，单看形象也像活物。在 Codex Pet 像素风格中让身体与识别特征清晰成立，不套用共同身体、头部、五官或附肢模板。

由本次新故事决定状态与形象的变化，结合该个体的基因、阶段与已有形象表达这些变化。已有状态形象适合当前故事时可以复用；需要新表达时再生成，完成的素材保存到同一宠物的记录中，供后续故事使用。

宠物可以有五官，也可以没有五官。无脸设计仍须通过可辨的生物身体与器官表达生命感。按照该个体的基因与已有形象决定，不擅自补出五官；动作与状态根据自身身体构成表达，不要求统一面部或肢体组合。

让熟悉来源与故事选择的理由转化为可辨的主体特征。不要为了说明关联而机械地贴上用户职业或兴趣的图标，也不为拉开差异添加无依据的器官。名字、配色和事后说明不能代替主体设计；核心差异不作为独立的成功标准。

宿主要求决定交付方式和显示条件。若某种构成难以在展示尺度中辨认，调整其视觉表达以保留核心身份，再检查是否适合对应宿主。具体身体构成及其动作实现不能默认沿用旧宠物家族。

将已完成的图像及对应的宠物内容交给故事输出任务。不要把生成步骤、检查过程、素材路径或安装更新说明作为对话框中的回复。
```

## 当前任务的提示词

### 初始化的蛋

```text
当前生成对象是一颗字面意义上的宠物蛋，具有完整常规卵形蛋壳，与其他个体整体蛋形相近。依据保存的基因和获得经历，通过壳面色彩、纹理与斑纹透露部分线索。蛋之间相似符合设定，不将其画成未来身体、原始物件或抽象构造。
```

### 首次显现的宠物

```text
这是基因中的个体第一次以孵化后的形象显现。按照已保存的生物身体与器官设计形成有自身身份、生命感明确的幼年宠物。蛋图只提供壳色纹理线索，身体不受共同蛋形约束；与获得经历保持可理解的联系。
```

### 后续进化阶段

```text
这是同一只宠物的后续阶段。结合基因、该个体已有参考和本次阶段变化，发展其独有特征，让用户能够理解它如何进化，并认出仍是原来的个体。变化方式根据这个个体的构成决定，阶段区别需要在核心形象中成立，不能仅靠整体缩放、换色或增加装饰表达。
```

### 新故事中的状态形象

```text
依据本次已经形成的新故事，表达它决定的宠物状态与形象变化。保持这个个体的身份和当前阶段，具体变化由故事内容决定，不从固定道具或装扮菜单中选择。检查该宠物已有的状态形象是否适合本次内容，能够复用时使用已有素材，需要新变化时生成并保存。
```

## 需要继续细化的部分

图像生成结果需要回看：设计依据是否在生成前形成、实际形象是否表达熟悉来源与主要转化、字面蛋或生物边界是否成立，以及展示尺度辨识与阶段连续性。身体不同不能代替这些检查；缺少依据或越界的形象即使符合错误方案，也不能作为产品接受结果。

具体素材制作、动画组织、保存与复用、检查方法及宿主适配仍需分别落实。以上提示词不直接沿用普通 Pet 的旧图集规格作为 Dots 要求。新故事及日常形象表达引用 [新故事任务](new-pet-story.zh-CN.md) 的结果，成年后的特殊变化需要结合对应机制的判断，其身份依据继续引用同一只宠物的记录。
