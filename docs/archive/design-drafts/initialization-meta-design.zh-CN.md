# 初始化元规则草案

本文保留初始化元规则的设计依据；0.5.0 实际运行文件为 [meta.md](../../../framework/prompts/meta.md)。开发者修改运行文件，具体形象和故事由初始化任务形成。对应 [产品设计](../v0.5/PRODUCT_DESIGN.zh-CN.md)。

## 规则的作用范围

规则用于领养故事、基因形成及初始化形象的生成。开发者修改实际运行模块来改变生成条件；某一只宠物已经形成的基因与形象记录单独保存。规则修改用于后续任务的指导，不自动重抽已有个体的基因。

元规则维持框架层的共同要求。每只宠物的识别特征在初始化时分别产生，之后成为该宠物自己的连续性依据。

## 可组合的元规则提示词

```text
由 Codex Agent 根据当前任务，从所在环境实际可用的上下文中自行选择相关资料与活动，理解用户。资料来源、取舍与参考范围由当次情况决定，不要求预先填写固定的用户资料表。

让用户与这只宠物的相遇有来由。根据选择的用户资料，寻找对用户有意义的联系，将其发展为获得蛋的经历与地点。涉及用户实际情况的叙述应有资料依据；宠物的探险和相遇情节可以虚构。保留用户事实与虚构经历之间的区别。

将基因生成视为元规则下的一次宠物设计。先从领养故事中的具体经历、地点及用户联系，选择人类熟悉的自然、文化形象或 IP 等作为灵感，记录借鉴什么、为什么适合这段相遇，以及如何影响主体形态和主要特征。来源保持开放，不建立候选清单，不编造用户偏好或既有来源设定。概念可作为主题，但主体需要具体可辨的熟悉形象来源。

随机性探索这些设计依据允许的诠释，不先拼罕见身体再补理由，也不以新奇或身体差异大作为成功标准。熟悉来源应参与主体构成；名字、配色、外贴图标和事后说明不能代替这份设计。同一故事可以支持不同设计，也可以自然产生相近的设计。

初始化的蛋是一颗完整常规卵形蛋，各个体的整体蛋形相近，主要以壳面色彩、纹理和斑纹表达差异。基因在初始化时形成，蛋壳只透露部分线索，孵化后才显现不同的身体构成。

孵化后的形象为有自身生物身体与明显器官的幻想宠物。来源保持开放，物体、概念和文化意象也需要通过拟生物或拟人方式形成生命角色；单看形象、不读名字与故事也能辨认为活物。整体构成与表达逻辑由个体决定，不预设物种或共同身体部件清单。此前形象例子只说明可能性，不构成候选范围。

五官可以有，也可以没有。无脸个体仍需可辨的生物身体、器官和生命感；不规定完整五官或固定的肢体组合。辨识度与状态表达由该个体自身的身体特征建立。

避免所有宠物只是同一底稿的换色，但不要求每对个体都具有不同身体。不为拉开差异添加无依据的器官。颜色、纹理、服装和装饰可以参与设计，主体的来源与故事依据也应有可辨表达。共同蛋形保留。

让同一只宠物能够延续自己的身份。初始化时记录对它有识别意义的特征、特征之间的关系，以及后续阶段如何发展这些特征。连续性依据由这个个体的设计产生，不要求所有宠物遵循相同的成长外形。阶段变化需要表现进化，并与这个个体的基因保持连贯。

采用 Codex Pet 的像素视觉语言，使核心特征在实际展示尺度上清晰可辨。视觉风格与工程输出要求适用于所生成的形象，不预先决定其物种、整体构成或部件。具体尺寸、透明背景、动画与交付格式由对应宿主要求提供。
```

## 如何检查规则是否有效

在生图前检查设计依据：来源是否具体可辨、为什么由这段相遇选择它、主要形态如何转化。实图再检查这些关系是否可见、蛋是否是字面蛋、孵化后是否像有身体与器官的活物，以及同一个体的跨阶段连续性。符合越界或缺少依据的方案，不能作为产品接受结果。

一种验证方向是固定领养故事，形成多份独立设计，逐个检查来源选择与形态依据。来源或身体相近不自动失败，身体不同也不自动成功。跨案例只换色、换纹理或换装可以帮助发现共同模板，但不能把差异量当作设计目标。蛋形相似、蛋壳主要换色和纹理符合产品边界。

另一个方向是让同一只宠物形成不同阶段的形象，观察其独有特征如何延续与发展。用户是否感到获得经历有意义、宠物与自己有关，仍需要用户的实际判断。

验证不要求覆盖预设的角色分类，也不以偏离既有形象越远越好作为目标。具体生成样本、判断方法和实现成本待后续确定。
