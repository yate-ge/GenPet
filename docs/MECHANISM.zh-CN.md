# GenPet：先有蛋，身份在孵化时形成

设计原则是 **未知 → 揭晓 → 熟悉 → 陪伴成长**。蛋不是缩小的宠物，也不是把预先完成的角色包进蛋壳。领养时系统既不生成幼体图，也不保存完整幼体形态；5 小时后才解析出生身份并生成第一张角色母版。

## 1. 领养：只建立一颗蛋

所有蛋共享普通卵形、像素颗粒、描边、有限色阶和受限动作语义。蛋壳以乳白或暖灰为主，个体差异只占很小的视觉面积：极淡色调、几颗不对称细点或抽象细纹。没有眼睛、嘴、耳朵、四肢、叶芽图案或可以辨认的生物剪影。不能把几颗斑点排成一张脸。

本地近期活动只轻微偏置色调；随机种子提供微小差异。证据不足时使用默认色调，不假称了解用户。设计目标是“这些蛋略有不同，但都不知道会孵出什么”。有些线索应当等出生之后才被回头认出，而不是在蛋上直接预告答案。

数据上只有蛋壳签名（色相、抽象纹样和种子），`hatchIdentity = null`。未知必须是真正尚未解析的状态，不能只是界面隐藏已经生成的角色。

## 2. 孵化前 5 小时：积累经历，不揭晓角色

直接读取本机 Codex 活动，提取构建、研究、创作、学习、休息等有限标签；不把聊天原文存进宠物记录，不推断用户人格。每个任务限权，缺少证据就保留未知。

蛋只能轻摇、倾斜、小幅挪动或跳动。它没有可眨的眼睛，也不会伸出手招呼。工作、等待和出错仍对应 Codex 原生状态，但通过受限的蛋壳动作来表达。

初版不会因某次任务立刻长出研究符号、工具、叶片或其他“谜底”。也不按工作量加快孵化；没有工作数据同样正常孵化。

## 3. 到点孵化：从蛋与这段经历向前生成

孵化时才进行一次出生决定：

`出生身份 = 有限的角色设计规则(蛋壳签名，孵化期活动标签，个体种子)`

先完整收集 `[领养时刻, 孵化时刻)` 的可用标签，再一次性解析身份。主体变化来自随机种子；活动只是小幅概率或形态参数偏置。因此不存在“程序员一定得到某物种”“研究者一定得到另一物种”的固定对照。

共享设计范围约束圆润身体、简洁像素五官、统一轮廓语言和动作可读性。在这个范围内，出生决定才选择身体比例、附属结构等有限组合。相似的蛋可以产生不同结果；不同活动也不会无限扩大物种范围。

图像生成只能参考蛋的微弱色调和一处抽象纹样线索，不继承“蛋形脸”，也不引用任何事先做好的幼体作为答案。第一张幼体母版通过检查后，才成为以后生长的身份参考。蛋母版与幼体母版分开保存。

出生决定记录算法版本、解析时间、证据数量和影响类别，便于解释和复现；不是把图像模型输出宣称为逐像素可复现。迟到的新活动不会再次抽取已经出生的身份。

## 4. 出生后：身份稳定，三个速度的变化

| 尺度 | 可变内容 | 不变内容 |
|---|---|---|
| 即时 | Codex 驱动的工作、等待、检视、失败等动作 | 动作含义、同一个角色 |
| 每 5 小时 | 与近期活动有关的小道具、当期表达版本 | 五官、身体类型、识别特征 |
| 每 24 小时 | 身体比例逐渐成熟、表达倾向缓慢变化、少量纪念细节 | 基础物种与已认可的身份 |

“长大”优先通过体态比例表达：身体逐渐舒展、头身比例缓慢变化，而不是每天换一个物种或只把图片等比放大。成长量采用 `sqrt(min(day/adultDays, 1))`（默认 `adultDays=21`）的有界曲线，第一日躯干相对出生目标约为 1.087、肢体约为 1.065，成年分别封顶于 1.4 和 1.3；第 7/21 日仍按原策略切换阶段。较早的变化更容易在 192×208 像素格里被看到。每次生成仍要实际图像验收，不能把数值更新自动等同于可见成长。

默认孵化后第 7 个完整成长日进入少年，第 21 天进入成熟。成熟后保留形态，用表达与少量细节延续故事。没有掉血、缺勤惩罚、连续打卡或生产力排名。

## 5. 为什么符合 GenFaceUI 的理论参考

统一的是设计者设定的可生成范围和交互语义；个性化的是范围内逐渐形成的具体个体。情境负责当期表达，出生后的母版负责身份连续性。用户可以关闭读取、冻结装扮和清除派生记录。这里新增的是“身份延迟形成”的设计机制，不声称它已被原论文验证。

## 6. 实现与演示的诚实边界

- 状态孵化与图像完成是两个事件。5 小时到点会解析身份；图像生成和检查需要额外时间。
- 新蛋必须先独立生成。历史 Moss 只作为独立像素角色示例，不是这颗蛋的预定后代。
- 真正的正向孵化演示必须先产生蛋，再推进独立演示时钟、加入模拟标签，最后依据新出生决定生成幼体；不能把两份预制图片的切换包装成正向生成。
- 初版原生表现是替换通过检查的 atlas，不承诺连续破壳电影式动画。当前版本使用本机调试通道确认同一悬浮 Pet 的自动刷新；通道不可用时必须报告显示未确认，不能以手动 Refresh 充当自动成长验收。
- 原生 Pet 用道具表达情境，完整场景暂只存在于独立的外部调试工具。

后续值得你定制的是：线索强度、允许出现的角色结构范围、活动影响的最大幅度、成长速度，以及生成频率/成本预算。当前采用“弱线索、统一家族、小幅活动偏置、出生后身份冻结”的默认组合。

## 7. 定时执行由 Codex 承担

Codex 原生 Scheduled Task → 插件计算是否跨越成长/情境边界 → 必要时运行 imagegen 和官方图集管线 → 验证通过后更新同一个原生 Pet。插件没有常驻轮询计时器，不依赖网页、系统 cron 或 launchd。

默认一个每小时检查的任务即可：孵化与情境规则为 5 小时，成长规则为孵化后每 24 小时；两者同次到期时合并为一个当前设计。逻辑时间以领养时间为准，实际出图还受检查频率、生成耗时和原生刷新影响。暂停定时任务不会倒退或惩罚宠物，下一次调用会按时间补算，且只生成当下状态。
