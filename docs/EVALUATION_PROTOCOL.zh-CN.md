# 个性化、成长与状态的验证方案

本方案把**程序映射**、**生成图像是否兑现映射**、**人是否读得出来**分开。已完成的 25 组合成映射、1000 seed 碰撞检查、三只同活动样本和当前角色第 1 日候选图集是前两类初步证据；它们不是不同真实用户的体验结果。

## 1. 程序层：可重复映射

固定活动标签、seed、时间与策略版本，重复运行领养、五小时孵化、五小时情境转换、第 1/7/21 日成长。记录蛋 DNA、出生身份、当前设计请求 ID、已验收素材 ID 与原生显示状态。检查同输入同结果；只改 seed 时出生身份目标有差异；只改活动时允许改变的目标按规则改变；只改时间时身份不变。将粗轮廓、纹理标记和色相碰撞率分别报告，不把参数不同等同于人眼可辨。

## 2. 生成层：受控图像实验

建议先取 4 种活动构成 × 6 个 seed，每格生成两次出生图像。另做两项配对：同活动不同 seed，以及同 seed 不同活动。固定蛋孵化过程，不从成体倒推蛋。对照图统一第 0 日、空手、同样的 192×208 格；另制灰度版，判断差异是否只靠颜色。记录每张图的真实输入摘要类别、seed、设计请求、生成尝试次数、官方 QA 与拒收原因。由不知道条件的评审标注头身轮廓、侧边附肢、永久小标记、脸、配色，以及是否符合宣称的约束。生成失败和修复也计入分母。

## 3. 人的理解：真实用户试验

建议招募 12–16 名自愿参与者，在本人知情下从本机 Codex 近期**用户消息**导出有限活动标签；不收集原文、系统消息、工具输出或项目机密。每位参与者先看自己的蛋与孵化过程，再看由实际标签生成的幼体。比较“本人真实标签 + 本人 seed”和“打乱标签 + 相同 seed”两种条件；展示顺序随机、道具统一空手。收集二选一的“哪个更贴近最近工作”、理由、映射可解释性与隐私接受程度。随后混入他人的角色，测同一角色在空手／不同道具／第 1、7、21 日图像中的身份识别；明确告知 7/21 日若是模拟加速，不把它当真实长期使用。

报告总体正确率及参与者内差异，也报告难以分辨、觉得刻板化、觉得被错误推断的案例。受试者“更喜欢某只”并不证明映射忠实；身份识别不等于活动映射被理解；短时模拟不能推断长期依恋或生产力收益。若样本尚未采集，只标为待验证。

## 4. 对成长与状态的独立检查

成长任务保持出生肖像和当前道具固定，比较相邻日、7 日和 21 日。先做盲序“是否同一只”“哪只更成熟”，再揭示时间，询问变化是否自然。记录体长／头高、肢体比例、原生单格可见性以及图集的动作连续性。五小时状态任务反过来固定身份与成长日，只切换道具，检查参与者能否说出当前场景的线索，且不会误以为换了宠物。记录逻辑到期、图集完成、原生画面确认三个时间点。

## 需要设计者最终决定

1. 真实参与者是否覆盖不同职业与 Codex 使用强度；建议先用 12–16 人做形成性检查，不作总体代表性声明。
2. 哪些近期活动标签适合公开给参与者看，以及被误判时的更正和删除方式。
3. 角色可接受的共同风格边界，以及“同一只”和“明显长大”的主观判定标准。
4. 生成预算和每格重复次数；次数不足时应报告方差未知。
5. 是否收集 7/21 日真实纵向反馈。若不收集，论文只描述模拟阶段的可读性。

以上决策不阻塞当前插件运行；它们决定研究结论能说到哪里。
