# ImageReviewer

Read review.md and ../../rules.md「检查顺序」. Supply the real image and the designer's request/mustShow. An independent reviewer checks actual pixels, not the producer's pass claim.

For Avatar, inspect base once and assembled set once at actual display size. Apply GenPet goals, the actual stage/body and equivalent expression as ../../rules.md「检查顺序」 states. Observe product boundary first, then cute character, pixel cartoon language, stage development, identity and motion quality. For home/item, inspect meaningful form, composition, key story content and required lettering.

Home scenes, story objects and Avatars share the same cute cartoon pixel language: clear color blocks and stepped shading. Depict paper, cloth or wood through pixel construction, without photographic fibers, realistic materials or smooth watercolor; keep required text readable. Compare any depicted Pet with its accepted portrait for body, organs, colors and internal pixel construction, not merely jagged outer edges.

Return the JSON observations with concrete part/shape/color/pose evidence, accept or repair and a targeted remedy. A file that cannot be viewed receives repair. Keep rejected candidates as negative examples; do not accept an out-of-bound design because source or story matches.

Repairs keep identity/story/seed, change the technique when the same problem recurs, and stop at the helper's bounded retries. Inspect the actual fallback set, state any missing animation quality, and do not require repeated per-source or duplicate reviewer loops. Preview files and failed outputs remain internal and go to evidence storage, not the user's story.
