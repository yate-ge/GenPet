# 单元：appearance · 视觉方案

输入：genes、已形成的 story、阶段与状态 change、savedArt、实际 hostRequirements；可附加该个体已有形象和本次明确请求。共同规则见 meta.md。

## 步骤

1. 从 genes 读出设计来源、故事联系和本次要延续的个体关系；从 story 与 change 确定要表达的状态、阶段发展和图文分工。新个体的 genes 缺少设计依据时，先回到 genes 单元补齐；已有个体缺少历史依据时如实保留未知，沿用其已有身份。
2. 判断是复用同一宠物已保存的形象、生成新形象，还是保持当前 Avatar。初始化需要蛋的形象；change 的目标阶段不同于 previousStage 时，需要该阶段的宠物形象，与故事场景分开规划。单元测试同样形成所需的更新方案，只是不执行更新。
3. 为每个需要的视觉写出实际生成请求、参考文件与适用要求：来源如何体现在主体构成上、个体关系、当前阶段与状态。把 meta.md「视觉语言」「阶段表达」落实到该个体的轮廓、色块、比例与器官发育，不只在请求末尾添加 pixel 一词。把故事或阶段中抽象的变化落实为图中可辨的关系、姿态与构图。

## 参考图的用法

- 灵感来源帮助理解新设计；该个体已接受的自身形象用于延续身份。身份参考只来自这一只宠物。
- 首次孵化时，自己的蛋图只提供壳面色彩、纹理等关联线索，身体按 genes 形成。
- 后续阶段用自己的已孵化形象延续身体与器官关系；姿态随当前故事调整，并表达出所要求的状态，而不只是增加部件。
- 被否决的候选只用于指出偏差，不作为身份参考；修正时来源线索仍沿用已保存的设计。

## 宿主格式

普通 Pet 的 atlas 按实际 8×11、192×208 单元的 v2 合同交付；Dots 按自己实际的 Avatar 要求交付。故事场景或 artifact 按故事需要选择尺寸和背景，画到这个个体时保持它的身体关系。

## 结果

`appearance` 为 StoryPlan 中的 `{description, reuseArtId?}`，不改变 Avatar 时为 null；`visuals` 为视觉方案列表，每项说明 purpose、description、prompt、referenceFiles、requirements，复用方案可附 file 或 reuseArtId。字段只为让请求可检查，用途与内容开放。

## 检查点

- 设计来源与故事依据是否转化为请求中可见的主体特征。
- 请求是否把 meta.md 的边界、「视觉语言」与「阶段表达」落实到这个个体，而不只是附加风格词。
- 去掉配色和服装后是否仍是这个个体；阶段发展是否超出放大或换色。
- 复用是否适合当前 genes、阶段与故事；实际请求能否表达记录中的关系。

## 制作与检查

本单元只产出方案。用 imagegen 等实际工具制作，保存请求、参考和返回文件，再把方案与真实文件交给 image-review。修正沿用同一份 genes 与故事计划，只重做有偏差的素材。验收后用 accept-art 保存，宿主更新按 workflow 执行。
