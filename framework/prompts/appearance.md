# 单元：appearance · 宠物形象（PetDesigner）

输入：genes、已形成的 story、阶段与状态 change、savedArt、实际 hostRequirements；可附加该个体已有形象和本次明确请求。规则见 meta.md。

判断是复用这只宠物已保存的形象、生成新形象，还是保持当前 Avatar。初始化需要蛋的形象；阶段进化与进入特殊形态需要新的宠物形象；离开特殊形态时通常复用该阶段原有的形象；故事让可见的状态变化（穿戴、饰品、手持、携带或使用的物件、坐具）时，生成或复用这只宠物的状态变体，只改变这些东西。本单元只设计宠物的 Avatar；故事的载体由 carrier 设计，家和家的全景图由 home 设计。新个体的 genes 缺少设计依据时先回到 genes 补齐。

每个视觉请求把来源、个体关系、阶段与状态落实到具体的轮廓、色块、比例、器官发育与姿态上，而不只是附加风格词；故事中抽象的变化落实为图中可辨的关系与构图。

## 参考图

- 身份参考只来自这一只宠物已接受的形象；被否决的候选只用于指出偏差。
- 首次孵化时，蛋图只提供壳面色彩、纹理等线索，身体按 genes 形成。
- 后续阶段用自己的已孵化形象延续身体与器官关系，姿态随故事调整。
- 特殊形态在同一身体上做出明显变体，仍能认出是这只宠物。
- 状态变体以该阶段已接受的形象作身份参考，只改变穿戴、手持等，不改变身体与器官；回到已有的状态时复用已保存的变体（reuseArtId），不重画。

## 宿主格式

普通 Pet 的 atlas 按 8×11、192×208 单元的 v2 合同交付；Dots 按自己的 Avatar 要求交付。载体与家的画幅由各自的单元决定，画到宠物时保持它的身体关系。

## 结果

`appearance` 为 StoryPlan 中的 `{description, reuseArtId?}`，不改变 Avatar 时为 null；`visuals` 为视觉方案列表，每项说明用途、描述、实际请求、参考文件与要求，复用方案可附 file 或 reuseArtId。

检查点：来源与故事依据是否转化为请求中可见的主体特征；去掉配色和服装后是否仍是这个个体；阶段发展是否超出放大或换色，特殊形态是否只是调色；状态变体去掉穿戴后是否仍是同一身体，物件在小尺寸下是否清楚、在整套动作里是否一致；复用是否适合当前基因、阶段与故事。
