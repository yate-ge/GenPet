# 单元：evolution · 阶段与变化判断

输入：context、当前 pet 记录（含 personality）、已经形成的 story；可附加用户明确的 /genpet-grow 调试请求。共同规则见 meta.md「故事与状态」「个体性格」。

## 步骤

1. 读取当前阶段与既有基因，比较本次资料和已有相关记录。Agent 自行选择参考范围与有意义的工作变化依据。
2. 先核对状态变化的用户原因与事实引用，再按性格形成状态表达。独立生活保持 pet.state.description 与原阶段。没有用户依据时不改变状态或身份形象；即使故事很精彩也不补造原因。
3. 根据近期工作内容是否变化判断是否进化。依据不足时保持原阶段。进化依据是工作内容的变化；时间经过、工作量和固定阈值都不是依据。性格影响反应方式，不充当进化触发条件。
4. 成年后的特殊变化结合用户一段时间的活动与随机性，延续个体、性格和经历。内容、持续方式由当次情况决定。

结果：stage 为 egg、hatchling、juvenile 或 adult；state 为故事与性格共同决定的状态描述；basis 简述用户原因、采用的 context 事实引用与变化判断；personalityEffect 说明性格如何影响反应，或为何保持当前状态；specialChange 在没有特殊变化时为 null，有变化时为开放描述。阶段向前发展，不能倒退。

检查点：每个状态、阶段或身份形象变化是否能回到实际用户事件；同一用户事件是否因性格而产生个体化反应；是否把临时状态写成性格改变；是否把天数、性格或工作量当作进化触发；阶段变化是否延续基因；特殊变化是否发生在成年阶段。

用户明确要求验证后续阶段时，可以按请求形成结果，在 basis 标明调试依据，不伪造工作变化。新故事、定时任务与 Dots 主动行为使用同一判断单元。

本单元只形成计划，不安装图像或宣告进化成功。下游 appearance 使用本结果，最终 output 核对实际完成状态。
