# 单元：ImageReviewer · 实际看图

输入：appearance、story-item 或 home 的 visual，以及 actualFile 的真实可读图像。先打开文件，按目标用途看原图与实际显示大小；读不到文件时 verdict 为 repair，说明缺失。

按 meta.md「检查顺序」记录具体部位、轮廓、颜色与结构。Avatar 先看产品边界、眼睛和可爱程度，再看设计理由与发育、连续性和故事变化；故事物件与家按目的和 mustShow 观察，图中文字逐字对照。透明背景只适用于要求透明的素材。代码检查格式，视觉审核不重做已完成的尺寸核验。

结果：`file` 为真实文件引用；`verdict` 为 accept 或 repair；`observations` 为 `{criterion, passed, observation}` 列表；`repair` 写具体修正或接受时 null。基准图和完成整套各审一次；整套按真实显示大小看动画和方向一致性。观察到缺陷再定向返工，不另做每张源图的重复审核。

修正影响产品边界、身份/阶段、故事变化、动作/方向可读性或必须内容的缺陷。无关这些的不显眼边缘像素等小瑕疵记录即可；不为反复润色重画已接受的行。

换装或道具变化还要看姿态是否在表达这次活动：目光、重心与接触关系可读，身体身份保持；只给中性摆拍像加衣物或道具，不算活动已经表达。

成长和临时特殊形态并列看原图及相同的显示尺寸，先忽略阶段名称和解释文字。成长是否真的表现出发育结构，普通与特殊是否有可辨的身体轮廓和构造差别？若只能靠标签、缩放或微小姿势区别，就修正具体身体表达，不用文字宣称效果。角色换装还要看实际衣型与活动能否读出区别，原身体是否保持。

检查点：实际看过，观察可定位；没把上游越界设计当画图成功；没有拿元数据、JSON、生成者自评替代视觉证据；补帧后的实际动作仍可辨并保留不足。失败候选和审核预览保留内部，接受不更新 Pet，由主流程更新同一个 ID。
