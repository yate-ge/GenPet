# Contributing to GenPet

Thanks for helping. Read [the architecture](docs/ARCHITECTURE.md) for how the pieces fit, and [AGENTS.md](AGENTS.md) for the repository layout and the product and design rules that every change follows. The product rules the plugin runs on are in [plugins/genpet/skills/genpet/rules.md](plugins/genpet/skills/genpet/rules.md).

## Setup

Use Node 22 or later.

```bash
npm ci
npm run verify:fast
```

`verify:fast` runs type checks, formatting and the unit tests. Run the checks that fit your change; do not add tests that only mirror wording or implementation.

## Where to edit

- `plugins/genpet/` is the only copy of the plugin: skills, debugger page, manifest and README. `src/` is the runtime source. `plugins/genpet/dist/` and `plugins/genpet/package.json` are generated by `npm run build:plugin`; do not edit them by hand.
- Write each rule once, in the file that owns it, and link to it elsewhere. When a unit's inputs or results change, change its prompt and `plugins/genpet/skills/genpet/host/units.json` together.
- Keep code and prompts small. The Agent chooses sources, context range, design, relationship and story content; code handles identity, persistence, host binding and the few agreed guarantees listed in AGENTS.md. Do not add activity taxonomies, personality presets, face templates or configuration for judgments the Agent can make.

## Records and hosts

- Records are version 3, one per Pet ID, with `soul`, `memory` and `state`. Keep immutable identity, existing source history and cloud IDs. Old saved field names stay readable.
- A story keeps the Pet ID resolved when it started.
- Host display, readback, refresh and selection are separate facts; a selection or refresh request does not prove what is displayed. No Pet path depends on Computer Use.
- Dots uses the same cloud Pet, accepted atlas and record brief through the host's own tools. There is one `genpet` package and one marketplace entry.

## Testing with a real Agent

Content and image checks follow the unit contracts in [host/units.md](plugins/genpet/skills/genpet/host/units.md) and the Agent acceptance suite: the cases are in [tests/agent/CASES.zh-CN.md](tests/agent/CASES.zh-CN.md) and the procedure in [tests/agent/README.zh-CN.md](tests/agent/README.zh-CN.md).

- A valid JSON result or a model's own pass claim is not semantic evidence. Keep the actual upstream results, look at the generated pixels and get an independent review.
- Use an isolated `CODEX_HOME` and a dedicated test Pet. Tests and upgrades must not adopt, age, reset or regenerate anyone's real Pet. Isolated tests cannot prove live display.
- Write test output under `output/`, which git ignores. Do not commit images, PDFs, logs or run output.

## Pull requests

Describe what changed and why, list the checks you ran and their results, and say what you could not verify. Releases follow [docs/RELEASING.md](docs/RELEASING.md) and are made by the maintainer.

Report security problems as described in [SECURITY.md](SECURITY.md), not in a public issue.
