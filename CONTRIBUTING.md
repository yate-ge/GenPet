# Development and release

Use [the architecture](docs/ARCHITECTURE.md) and [current plan](docs/DEVELOPMENT_PLAN.zh-CN.md) for the intended scope. Edit framework/ (prompts, references, skills, debugger-web) and src/; plugin runtime and shared copies are generated. Keep code and instructions small. Agent chooses sources, context range, design, relationship and story content; code supports identity, persistence, host binding, seeded selection and the explicitly agreed growth/variety guarantees. Do not add activity taxonomies, personality presets, face templates or configuration for judgments Agent can make.

[framework/skills/genpet/rules.md](framework/skills/genpet/rules.md) is the product-rule source. unit-request prepends it; each unit contains its inputs, result and concrete review points. Each Designer has a folder under framework/skills/genpet/designers/ with its README and the unit prompts it owns; these do not add menu entries. The separate genpet-chat entry is conversation; naming belongs to genpet. Change the affected prompt and units.json together when a contract changes. New names are reason, designReason, source, factIds, story-item and ImageReviewer; old saved aliases remain readable.

v3 records are per Pet ID with soul, memory and state. Preserve immutable identity, existing source history and cloud IDs; complete memory/state/history atomically. Imported old records fill only missing information once after explicit import. A story retains the Pet ID resolved at its start. Tests and upgrades must not adopt, age, reset or regenerate the user's Pet.

There is one genpet package and marketplace entry. Dots uses the same cloud Pet, accepted atlas and record/brief, through actual host tools; it has no separate package or legacy Avatar format. Rebuild with npm run build:plugin after source changes. Ensure removed skills/prompts do not survive in the generated package. Host display, readback, refresh and selection are separate facts; neither selection nor refresh is proof of displayed art. No Pet path depends on Computer Use.

Use Node 22+, npm ci and npm run verify:fast (types, formatting, tests). Run checks appropriate to the change; do not add tests that only mirror wording or implementation. Content and image checks follow [generation-units](framework/skills/genpet/host/units.md) and [the A/T/S/V/C/E/G/U/D/M Agent suite](tests/agent/README.zh-CN.md). Contract validity and a model's self-evaluation are not semantic evidence. Freeze actual upstream results, inspect actual generated pixels and retain independent observations. Live host tests need a dedicated test Pet/cloud ID; isolated home tests cannot prove live display.

Keep every development/test artifact: reports, raw inputs/results, stories, images, rejected candidates, snapshots and run output. Upload them to the user's Google Drive, preserve local pending uploads, and never commit them. Only docs/evidence/README.md is the tracked evidence summary index. Keep the clone small because marketplace checkout has a fixed timeout. Do not put images, PDFs or logs in git.

Publish one public version after the whole approved plan is implemented and verified; intermediate edits do not each get a version. Before publishing increment semantic version consistently in root package.json, both package-lock locations, plugins/genpet/.codex-plugin/plugin.json and generated package.json. Fetch origin/main (or the explicitly configured release base), run npm run verify:release, and do not change the comparison base just to pass. The gate builds and validates the deliverable in an isolated home.

When installing from an existing marketplace, refresh its source even if already added or currently uninstalled. Verify the installed manifest and all source hashes with scripts/verify-install.mjs, report marketplace commit, version and installed path. New chats load the new skills; do not claim active chats have forgotten old instructions. See AGENTS.md for all release invariants.
