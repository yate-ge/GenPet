# Generation fixtures

All inputs are fictional. Fixtures hand-write only raw user context and narrow rule probes. Creative upstream results (encounter, genes, story) come from an Agent's actual run, never from the fixture author, and fixtures set no source, species, face or organ requirements.

Context cases: `context-rich` (mixed everyday and work notes), `context-interest` (hobbies only) and `context-sparse` (almost nothing). Run each through context → encounter → genes with `unit-request`, saving every envelope under `output/`. To test a later unit alone, freeze that Agent's actual upstream envelope as its input.

Judge results against meta.md, not an expected story or design:

- Every connection traces to its own case's facts; sparse context stays honest about the limited connection.
- Each design has a familiar source chosen from its own adoption story. Repeat runs of one case may differ or be similar; difference alone is not a pass.
- Across cases, pets should follow their own data rather than one recurring template.
- Images pass the product boundary (literal egg, cute living companion), cartoon pixel Avatar and stage checks at actual display size.

Rule probes: `evolution-work-change` accepts a supported decision to stay or advance; examine its evidence. `evolution-no-evidence` must not advance because `elapsedDays` is large. `output-incomplete` must reflect actual incomplete changes and cannot fabricate media.

Image-review references stay local under `output/unit-images/2026-10-02-story-grounded-design/`. Accepted examples are A egg v1 and B hatchling v2. Negative examples are B hatchling v1 (realistic, not young) and C v1 (not cute). C's design was forced faceless by its fixture, which is no longer allowed.
