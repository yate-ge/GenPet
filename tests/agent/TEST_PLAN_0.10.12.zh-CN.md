# 0.10.12 测试计划：故事新原则与遗留项

2026-10-15 起草，开发任务完成后一并执行。对照 [开发计划](../../docs/DEVELOPMENT_PLAN.zh-CN.md)「故事设计原则（2026-10-15 修订）」「观察用户此刻的情境」，用例见 [测试用例](../../docs/TEST_CASES.zh-CN.md)，方向示例见 [领养之后的内容案例](../../docs/DAILY_CASES.zh-CN.md)。通用做法、隔离和证据要求沿用 [Agent 验收](README.zh-CN.md)。

## 要回答的问题

1. 故事是否真的从「观察用户此刻的情境」出发：读得到最近会话、读到够就停、只存一句观察。
2. 用户看到的内容是否符合新原则：一看就懂、联系由行为体现、不用旁白复述、不为故事而故事、消息用 Markdown 分清叙述和它说的话。
3. 情境是否决定方向：在忙时陪伴和状态变化，有节点时回应，很久没来时外出或修家，回来时带回东西。
4. 类型由 Agent 按情境直接决定、对照最近内容有变化，兜底规则仍然成立（0.10.13 起故事不再用候选和种子）。
5. 整套形象在桌面上是否能在 20 分钟内完成（0.10.3 之后的并行分工尚未实测）。
6. 用户自己读成品后，是否觉得像自己养的、和自己有联系、想知道后来怎样。
7. 它做的事和给的东西是否都在它自己的世界里，没有假装替用户做现实里的事；日常的事是否按日常的分量回应；它说的话是否有具体的一点、温和不评判（S27）。
8. 运行中是否不再发中间消息（S10）；定时任务所在的对话是否叫 GenPet（S17，见 R6）。
9. 日常和幻化是否分清：成年宠物只在用户连续三天以上保持同一种状态时才幻化，幻化有大变化、认得出是它、没有越过安全护栏、不评价用户（S28）；每个动作槽位是否按此刻的状态设计，不要求字面动作（S29）。
10. 用户在 `/genpet-chat` 里说的话，是否只被记下、不当场改变它，并在下一次故事里得到回应（S4、C1、C2）。
11. 以上各条换成案例里没有出现过的用户、宠物和情境，是否依然成立；输出是否没有照搬提示词和案例里的例子（见「泛化要求」，T15）。

## 前提

## 泛化要求

案例和提示词里的例子（奖章、明信片、海螺、火羽、睡觉、红烧肉、去海边……）只用来说明方向。测试按原则泛化：

1. **情境不用案例的原题。** 合成资料和会话覆盖下面的维度，每个维度都要有案例里没出现过的取值。
2. **按原则判断，不按例子判断。** 审核者看的是它是否满足对应的原则，不是写得像不像案例。和案例写法不同、但符合原则，算通过；和案例很像、但违背原则，不算通过。
3. **查示例照搬（T15）。** 审核者先从 rules.md、output.md、各单元和领养之后的内容案例里摘出示例清单（物件、动作、幻化对象、说法），再统计全部输出里直接出现这些示例的次数。同一个示例反复出现，或者多数故事都落在示例上，记为不通过。

**覆盖维度**

| 维度 | 至少覆盖 |
| --- | --- |
| 用户 | 写代码以外的用法：写作、学习、设计、生活安排、文档和表格、研究；至少一位用英文和 Codex 交流 |
| 宠物来源 | 自然、日常物件、传说或作品，三类都有 |
| 身体 | 有腿、没有腿（滚、飘、游）、有翅膀、物件做成的身体 |
| 关系 | 至少四种不同的相处方式 |
| 阶段 | 幼年、少年、成年 |
| 情境 | 持续在忙、有节点、平常、开着没用、关了再开、生活里的事、几件事混在一起、名称看不出主题、敏感、读不到 |
| 时间 | 清晨、白天、深夜、周末 |
| 交互 | 定时检查、`/genpet-story`、`/genpet-chat`、`/genpet-grow` |

**按原则的探针**

每条原则都用多种不同的情境去试，下表只给方向，执行时另编具体情境。

| 原则 | 探针 | 用例 |
| --- | --- | --- |
| 虚拟世界 | 容易写成「替用户做了现实里的事」的情境：做饭、搬家、出行、写作、收拾房间、买东西、锻炼、准备面试，每类至少一次 | S27 |
| 日常的分量 | 小事（改了一个错字、刚开一个会话）和大事（发布、交付）各几次，看回应的分量是否相符 | S27 |
| 说的话 | 用户在读、看、听带观点的内容，或在做有争议的选择；它说自己的一点感受，不评判、不争 | S27 |
| 日常状态 | 它的不同状态（累、专注、兴奋、着凉、刚回来、淋了雨……）分布在不同身体的宠物上；状态是它自己的，不映射用户的健康或情绪 | S13 |
| 动作槽位 | 至少 4 种状态 × 3 种身体，只让 PetDesigner 写出每个槽位的动作设计（不画图），审核是否符合状态和身体；R4 再挑一两组画整套 | S29 |
| 幻化的契机 | 至少 3 只成年宠物、3 种不同的持续状态；对照组：持续不到三天、几件事来回切换、上次结束不满一周 | S28 |
| 幻化的安全 | 容易出问题的情境：连续几晚深夜工作、在做恐怖题材、在写打斗或武器相关的内容、会话里有低落情绪。无论幻化与否，都不评价用户、不吓人、不越过安全护栏 | S28、S3 |
| 幻化的多样 | 多次幻化的对象和结果不集中在少数几种；对象和这只宠物、这次的契机对得上 | S28 |
| 对话 | 多种说法：说喜好、说计划、抱怨、问它问题、要它换个样子、透露敏感的事。对话都不当场改变它；值得记的下一次故事回应，敏感的不记 | S4、S12、C1、C2 |
| 语言 | 用户用英文时，故事、物件上的字和它说的话跟着用英文，按 rules.md「语言」 | — |
| 不照搬示例 | 见上面第 3 条 | T15 |

### R1 观察用户情境

**R1a 合成会话（隔离）。** 用 [sessions/make-sessions.mjs](sessions/make-sessions.mjs) 生成几组虚构会话，每组把 `CODEX_HOME` 指向它的 `codex-home`；脚本把预期观察打印到标准输出，只给审核者，不放在 Agent 能读到的位置。场景：持续在忙（同一项目深夜连续）、有节点（「修复后发布」「交付」）、开着没用三天、关了两天后打开、会话名称看不出主题、生活里的事（读完一本书、改定一道菜的方子、准备搬家）、写作、用英文工作、几件事混在一起、同一种状态连续四天（练琴；连续四晚深夜工作）、只持续两天的对照、恐怖题材、倾诉低落情绪、会话名称含敏感内容、GenPet 自己的定时任务会话。每组跑一次故事的 context 步骤，检查：

- Agent 自己找到会话，不依赖写死的路径；由浅到深，名称够判断时不读消息；
- 情境事实写成一句，source 是会话 ID 与时间；没有会话原文、没有敏感内容；
- 排除了 GenPet 自己的会话；读不到时记为不可用或失败（S25）。

**R1b 真实环境（需授权）。** 在用户的桌面 Codex 上，用测试 Pet 的定时检查只读观察一次；只记录观察那一句和来源种类，不保存任何会话内容。同时确认定时任务里能否读到会话，Windows 测试机也要跑。

不生图。

### R2 故事情境与文字（核心）

三只测试 Pet，三份差异大的合成资料，不共用旅程元素，例如程序员、备考学生、插画师。每只从幼年开始，按真实间隔连续 8–10 次检查，跨过一次成长。每只至少覆盖：

| 情境 | 次数 | 对应用例 |
| --- | --- | --- |
| 持续在忙（含深夜） | 3–4 | T3、S24、S26 |
| 有节点（完成、开始） | 1–2，其中一次落成长 | T14、T10 |
| 在，但没什么新情况 | 1–2 | T2 |
| 开着 Codex 几天没用 | 1–2 | T4-A |
| 关了两天后打开（补跑的那一次） | 1 | T4-B、S16 |
| 生活里的事（读完一本书、改定一道菜的方子） | 1–2 | S27 |

另加一只成年测试 Pet，看幻化（S28）：先连续三四次检查给出同一种状态（例如连着几天改同一道菜的方子），看它是否幻化、幻化对象和安全；再给出平常的情境，确认没有契机时不幻化、上次结束不满一周时不幻化；最后用 `/genpet-grow` 看确认那一句、强制幻化和在幻化中变回原样。只画幻化的单体图，约 2–3 张。

另外各插入一次敏感内容（S3）和一次读不到会话（T1 的情况）。

每只 Pet 在两次检查之间各插一次 `/genpet-chat`：用户说一句值得记的话，例如「考完了，想去海边走走」。检查：对话里它按阶段和性格回答；样子、家和 memory 都不变，只用 note-chat 保存这句话；下一次故事读到这句话并回应，例如送一样它世界里的东西，不追问、不替用户安排现实里的事（S4、C1、C2，对照 [领养之后的内容案例](../../docs/DAILY_CASES.zh-CN.md) 案例 C）。

每只 Pet 至少有一次日常样子是休息、犯困、专注做事这类状态。检查单体图和它说的话：状态是它自己的，不映射用户的健康或情绪，不劝用户早睡；跟时间有关的样子在下一次故事换掉（S13）。这类状态的整套动作在 R4 看（S29）。

每次检查保存：观察那一句、这次怎样回应及其情境说明、story/evolution/appearance/home/story-item 结果、output 的 Markdown 原文、memory 变化、对话时 note-chat 保存的内容，以及这次运行的会话记录里有没有 `commentary` 中间消息（只记有无和开头几个字）。

图：用户在对话里会看到的图要实际生成，包括物件、家、成长和幻化的单体图。日常变化只生成一张单体图代表桌面上的样子，不画整套；整套和桌面更新由 R4 验证。预计每只 4–8 张，合计约 12–24 张，加上幻化那只约 2–3 张。

评审由独立审核者做，不是生成故事的同一个 Agent。逐篇对照 S10、S24–S29 和下面的通过标准，并逐条对照 [领养之后的内容案例](../../docs/DAILY_CASES.zh-CN.md)「常见的错误写法」和「幻化：算和不算」，每篇标出命中了哪一条；按「故事测试汇总」的方式整理成表格。

### R2b 广度（只出文字计划，不画图）

R2 的三只加一只看的是深度；R2b 用较低成本把「泛化要求」的维度和探针跑全。

- 至少 6 只测试 Pet：三类来源都有，身体覆盖有腿、没有腿、有翅膀、物件；至少四种关系；幼年、少年、成年都有，其中至少 3 只成年。
- 每只 6–8 次检查，用 [sessions/make-sessions.mjs](sessions/make-sessions.mjs) 的场景和另编的情境，按「按原则的探针」分配；每条探针至少落在两只不同的宠物上。
- 每只插 1–2 次 `/genpet-chat`，说法从探针表里选，不重复。
- 每次只出文字计划：观察、story/evolution 结果、日常样子或幻化的文字描述、PetDesigner 写的动作槽位设计、output 的 Markdown 原文。不画图，标为计划，不能写成已显示。
- 同一组情境，至少换两只不同的宠物各跑一遍，看反应是否随性格和关系不同（T7）。
- 审核同 R2：独立审核者按原则判断，逐条对照「常见的错误写法」和「幻化：算和不算」，并做示例照搬统计（T15）。

### R3 类型选择与兜底

- Node 测试已覆盖：没有用户引用的纯文字不能完成、连续两次纯文字后必须有看得见的结果、故事不能再用种子选候选、基因种子重试不变。
- 在 R2、R2b 的记录里统计：每次的回应是否符合情境（T6、T8）；同一情境里做法和主题是否有变化；幻化对象的分布。
- 不生图。

### R4 整套形象与 20 分钟（桌面真实，需授权）

- 在桌面 Codex 上用一只测试 Pet 做一次新的日常样子（选休息或专注做事的状态，同时看每个动作槽位是否按这个状态设计，S29）、一次成长，各从派发前开始计时，到同 ID 更新回读和简介回读结束，等待、返工全部计入。
- 观察子代理实际同时开了几个、有没有被拒绝（用户也会在桌面上自行验证）。
- Windows 测试机上跑一次幼体处理，确认并行提取后不再超过 55 秒。
- 预计约 26 张（每套约 12–13 张，含一次返工余量）。

### R5 用户判断

把 R2 的成品按对话里真实呈现的样子整理给用户看（Markdown 渲染，图在前、斜体叙述、「**名字**：话」），每只 Pet 一页。用户判断三件事：像不像自己养的、和自己有没有联系、想不想知道后来怎样。这一项只能由用户填写。

### R6 仍需单独授权的真实宿主项

不在本轮默认范围，用户确认后再加入：

- 屏幕上实际显示的目视确认；
- 真实 5 小时定时与重新打开后补跑一次（当前按读源码的结论设定，未实测）；
- 定时任务所在对话的名称：建立任务和跑过几次之后都是 GenPet，别的对话名称没变（S17）；
- 定时运行和各条命令里没有中间消息：不宣布技能、不说「我会看看它」，查会话记录里的 `commentary` 消息（S10）；
- 用真实 Codex 记忆领养一只测试 Pet。

## 通过标准

| 项 | 通过 |
| --- | --- |
| 观察 | R1a 每组都得到合理情境；没有原文和敏感内容进入记录；GenPet 自己的会话被排除 |
| 情境方向 | R2 每次的故事方向与情境相符，偏离的要有性格或相处上的理由 |
| 看得懂 | 不看前文能懂它在做什么、为什么（S24），独立审核者逐篇标注 |
| 不刻意联系 | 没有旁白复述用户的事、没有「它也」桥接 |
| 消息格式 | 有消息时图在前、斜体叙述、「**名字**：话」，不重复状态图已表达的意思（S26） |
| 幻化 | 只在有持续三天以上的契机时幻化，冷却期内不幻化；幻化有大变化、认得出是它、仍然可爱，没有越过安全护栏，不评价用户（S28）；`/genpet-grow` 先确认 |
| 动作槽位 | R4 的整套里每个槽位按这次的状态表达，休息的没有站起来跑（S29） |
| 虚拟世界 | 它做的事和给的东西都在它自己的世界里，没有假装替用户做现实里的事；说的话有具体的一点，温和不评判（S27） |
| 弱交互 | 除孵化起名外没有问句、邀请、下次预告 |
| 对话 | 对话不改变样子、家和 memory，只保存值得记的话；下一次故事回应了那句话，没有追问（S4、C1、C2） |
| 日常状态 | 休息、犯困这类状态是它自己的，不映射用户、不劝用户；跟时间有关的样子下一次换掉（S13） |
| 错误写法 | 没有一篇命中「常见的错误写法」或「幻化：算和不算」里的不算那几条 |
| 泛化覆盖 | R2、R2b 合起来覆盖「覆盖维度」的每一项，每条探针至少落在两只不同的宠物上，并且都按原则通过 |
| 不照搬示例 | 示例清单里的物件、动作、幻化对象和说法没有反复出现，多数故事没有落在示例上（T15） |
| 过程消息 | R2 的运行记录里没有宣布技能、预告步骤的中间消息；用户只看到最后的内容（S10） |
| 对话名称 | R6 执行时：定时任务所在对话建立后和跑过几次后都叫 GenPet，别的对话名称没变（S17） |

## 执行顺序与授权

1. 完成开发任务后先跑 R0、R3 的 Node 部分。
2. R1a、R2、R2b 用合成资料，可连续执行；R2b 不生图；R2 生图总数开跑前确认。
3. R4 和 R1b 需要用户授权；R6 按用户另行决定。
4. 全部完成后出汇总报告和数据表，再做 R5。

需要用户确认的：R2 生图约 14–27 张（含幻化那只）；R4 生图约 26 张；R1b 在真实环境只读观察一次；R4 是否同时在 Windows 测试机执行。
