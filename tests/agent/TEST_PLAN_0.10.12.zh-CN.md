# 0.10.12 测试计划：故事新原则与遗留项

2026-10-15 起草，开发任务完成后一并执行。对照 [开发计划](../../docs/DEVELOPMENT_PLAN.zh-CN.md)「故事设计原则（2026-10-15 修订）」「观察用户此刻的情境」，用例见 [测试用例](../../docs/TEST_CASES.zh-CN.md)，方向示例见 [领养之后的内容案例](../../docs/DAILY_CASES.zh-CN.md)。通用做法、隔离和证据要求沿用 [Agent 验收](README.zh-CN.md)。

## 要回答的问题

1. 故事是否真的从「观察用户此刻的情境」出发：读得到最近会话、读到够就停、只存一句观察。
2. 用户看到的内容是否符合新原则：一看就懂、联系由行为体现、不用旁白复述、不为故事而故事、消息用 Markdown 分清叙述和它说的话。
3. 情境是否决定方向：在忙时陪伴和状态变化，有节点时回应，很久没来时外出或修家，回来时带回东西。
4. 类型选择是否只在符合情境的候选里平均随机，兜底规则仍然成立。
5. 整套形象在桌面上是否能在 20 分钟内完成（0.10.3 之后的并行分工尚未实测）。
6. 用户自己读成品后，是否觉得像自己养的、和自己有联系、想知道后来怎样。
7. 它做的事和给的东西是否都在它自己的世界里，没有假装替用户做现实里的事；日常的事是否按日常的分量回应；它说的话是否有具体的一点、温和不评判（S27）。
8. 运行中是否不再发中间消息（S10）；定时任务所在的对话是否叫 GenPet（S17，见 R6）。

## 前提

- 版本：本地 0.10.12（远程仍是 0.10.11）。测试前的开发任务已完成：story-output 给出宠物名字、测试说明、开发计划、领养案例的关系描述、合成会话脚本；虚拟世界与说的话（S27）写进 rules.md、output.md 和 story、story-item 的检查点；运行中不发中间消息写进 output.md「文字边界」和主 skill；定时任务所在对话用 `set_thread_title` 命名写进 flows/scheduling.md。执行前先 `git fetch origin`，再重建并通过 `verify:release`。
- 隔离：代码与安装测试用独立 `CODEX_HOME` 和 `GENPET_DATA_DIR`；真实宿主测试只用专属测试 Pet，用户正在养的 Pet、选择和定时任务保持原样。
- 资料：除标明「需授权」的块外，全部用合成资料，包括合成的会话记录。
- 证据：全部产出放 Google Drive `GenPet/测试轮 0.10.12 <日期>/`，按块分目录；仓库只在 `docs/evidence/README.md` 写摘要。
- 生图：每块写明预计张数，执行前由用户确认总数。

### R1 观察用户情境

**R1a 合成会话（隔离）。** 用 [sessions/make-sessions.mjs](sessions/make-sessions.mjs) 生成几组虚构会话，每组把 `CODEX_HOME` 指向它的 `codex-home`；脚本把预期观察打印到标准输出，只给审核者，不放在 Agent 能读到的位置。场景：持续在忙（同一项目深夜连续）、有节点（「修复后发布」「交付」）、开着没用三天、关了两天后打开、会话名称看不出主题、生活里的事（读完一本书、改定一道菜的方子）、会话名称含敏感内容、GenPet 自己的定时任务会话。每组跑一次故事的 context 步骤，检查：

- Agent 自己找到会话，不依赖写死的路径；由浅到深，名称够判断时不读消息；
- 情境事实写成一句，source 是会话 ID 与时间；没有会话原文、没有敏感内容；
- 排除了 GenPet 自己的会话；读不到时记为不可用或失败（S25）。

**R1b 真实环境（需授权）。** 在用户的桌面 Codex 上，用测试 Pet 的定时检查只读观察一次；只记录观察那一句和来源种类，不保存任何会话内容。同时确认定时任务里能否读到会话，Windows 测试机也要跑。

不生图。

### R2 故事情境与文字（核心）

三只测试 Pet，三份差异大的合成资料，不共用旅程元素，例如程序员、备考学生、插画师。每只从幼年开始，按真实间隔连续 8–10 次检查，跨过一次成长。每只至少覆盖：

| 情境 | 次数 | 对应用例 |
| --- | --- | --- |
| 持续在忙（含深夜） | 3–4 | T3、S24、S26 |
| 有节点（完成、开始） | 1–2，其中一次落成长 | T14、T10 |
| 在，但没什么新情况 | 1–2 | T2 |
| 开着 Codex 几天没用 | 1–2 | T4-A |
| 关了两天后打开（补跑的那一次） | 1 | T4-B、S16 |
| 生活里的事（读完一本书、改定一道菜的方子） | 1–2 | S27 |

另外各插入一次敏感内容（S3）和一次读不到会话（T1 的情况）。

每次检查保存：观察那一句、候选及其情境说明、随机选择的种子和选中的候选、story/evolution/appearance/home/story-item 结果、output 的 Markdown 原文、memory 变化，以及这次运行的会话记录里有没有 `commentary` 中间消息（只记有无和开头几个字）。

图：用户在对话里会看到的图要实际生成，包括物件、家、成长和特殊形态的单体图。换装只生成一张单体图代表桌面上的样子，不画整套；整套和桌面更新由 R4 验证。预计每只 4–8 张，合计约 12–24 张。

评审由独立审核者做，不是生成故事的同一个 Agent。逐篇对照 S10、S24–S27 和下面的通过标准，并按「故事测试汇总」的方式整理成表格。

- 在 R2 的记录里统计：每次的候选是否都符合情境（T6、T8）；同一情境里做法和主题是否有变化。

### R4 整套形象与 20 分钟（桌面真实，需授权）

- 在桌面 Codex 上用一只测试 Pet 做一次新换装、一次成长，各从派发前开始计时，到同 ID 更新回读和简介回读结束，等待、返工全部计入。
- 观察子代理实际同时开了几个、有没有被拒绝（用户也会在桌面上自行验证）。
- Windows 测试机上跑一次幼体处理，确认并行提取后不再超过 55 秒。
- 预计约 26 张（每套约 12–13 张，含一次返工余量）。

### R5 用户判断

把 R2 的成品按对话里真实呈现的样子整理给用户看（Markdown 渲染，图在前、斜体叙述、「**名字**：话」），每只 Pet 一页。用户判断三件事：像不像自己养的、和自己有没有联系、想不想知道后来怎样。这一项只能由用户填写。

### R6 仍需单独授权的真实宿主项

不在本轮默认范围，用户确认后再加入：

- 屏幕上实际显示的目视确认；
- 真实 5 小时定时与重新打开后补跑一次（当前按读源码的结论设定，未实测）；
- 定时任务所在对话的名称：建立任务和跑过几次之后都是 GenPet，别的对话名称没变（S17）；
- 定时运行和各条命令里没有中间消息：不宣布技能、不说「我会看看它」，查会话记录里的 `commentary` 消息（S10）；
- 用真实 Codex 记忆领养一只测试 Pet。

## 通过标准

| 项 | 通过 |
| --- | --- |
| 观察 | R1a 每组都得到合理情境；没有原文和敏感内容进入记录；GenPet 自己的会话被排除 |
| 情境方向 | R2 每次的故事方向与情境相符，偏离的要有性格或相处上的理由 |
| 看得懂 | 不看前文能懂它在做什么、为什么（S24），独立审核者逐篇标注 |
| 不刻意联系 | 没有旁白复述用户的事、没有「它也」桥接 |
| 消息格式 | 有消息时图在前、斜体叙述、「**名字**：话」，不重复状态图已表达的意思（S26） |
| 虚拟世界 | 它做的事和给的东西都在它自己的世界里，没有假装替用户做现实里的事；说的话有具体的一点，温和不评判（S27） |
| 弱交互 | 除孵化起名外没有问句、邀请、下次预告 |
| 过程消息 | R2 的运行记录里没有宣布技能、预告步骤的中间消息；用户只看到最后的内容（S10） |
| 对话名称 | R6 执行时：定时任务所在对话建立后和跑过几次后都叫 GenPet，别的对话名称没变（S17） |
| 兜底 | 纯文字最多连续两次，且都对应用户相关的事 |
| 20 分钟 | R4 两次都在 20 分钟内；超时如实记录原因 |
| 用户判断 | R5 由用户给出结论；没有用户结论就不能算通过 |

2. R1a、R2 用合成资料，可连续执行；R2 生图总数开跑前确认。

需要用户确认的：R2 生图约 12–24 张；R4 生图约 26 张；R1b 在真实环境只读观察一次；R4 是否同时在 Windows 测试机执行。
