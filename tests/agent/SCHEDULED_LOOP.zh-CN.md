# 核心循环测试：定时运行推动故事

GenPet 的核心玩法是 `/genpet-start` 之后由 Codex/Dots 定时运行（以及 Dots 主动行为）推动故事、状态与进化；斜杠命令只是测试和金手指。M1–M5 只单独测试生成单元，这里在隔离环境中验证宿主定时循环能建立、触发并走完整流程。

## 不重复测的部分

`npm test` 已覆盖：`due` 取当天最近一个已到的时段、同一时段完成后不再到期、同一触发 ID 不生成第二篇、未完成的故事必须先继续。这里只看工程测试证明不了、必须在宿主里观察的事。

## 要回答的问题

| # | 问题 | 为什么重要 |
| --- | --- | --- |
| Q1 | 定时任务是否在第一篇故事完成后建立，且只建立一次 | 重装插件、重启宿主或重复 start 不能多出任务 |
| Q2 | 定时会话里 Agent 实际能拿到哪些用户资料 | 决定故事能否与用户有关、进化能否发生；拿不到时宠物会长期只有独立生活 |
| Q3 | 每次运行的决定是否合理 | 继续未完成的故事、写新故事或保持安静，都要能说出理由 |
| Q4 | 宿主层面的重试、错过与并发 | 睡眠后醒来只补最近一次；重复触发不出两篇；Dots 主动行为与定时同时发生不产生两个未完成故事 |
| Q5 | 多日连续性 | 故事是否多样、状态变化是否都有用户原因、进化是否只来自有意义的变化而不是时间 |
| Q6 | 用户看到什么、在哪里看到 | 定时运行的输出出现在哪个对话或通知里，是否只有故事和图 |
| Q7 | 形象更新 | 状态或阶段变化时按宠物 ID 更新宿主形象；正在显示时立即刷新，未显示时不改变用户的选择 |

## 隔离测试（当天完成）

目的：确认定时任务能建立、能被触发、能走完整流程，不碰真实宠物。

1. 准备隔离目录：

   ```bash
   RUN="$PWD/output/agent-tests/$(date +%F)-loop"
   export GENPET_DATA_DIR="$RUN/data" CODEX_HOME="$RUN/codex-home" GENPET_SKIP_NATIVE_REFRESH=1
   ```

   先确认宿主的定时任务能否带上这些环境变量运行。不能的话，本测试只验证 Q1、Q3、Q6 中不依赖数据目录的部分，并在记录中写明。
2. 在新对话中运行 `/genpet-start`，完成领养，检查 Q1：宿主里只有一个 GenPet 任务，`status` 中 `schedule.reference` 与实际任务一致。再运行一次 `/genpet-start`、重装一次插件，任务仍只有一个。
3. 用宿主的“立即运行”触发这个任务，在不同情况下各一次：
   - 刚到一个时段且尚未运行：应形成一篇故事。
   - 同一时段再触发一次：`due` 为 false，不应生成第二篇。
   - 人为留下一个未完成的故事（例如在出图前中断），再触发：应先继续它。
4. 每次运行后记录一行（格式见下），并检查 Q3、Q6。

## 交给真实用户端到端测试

Q2（定时会话能拿到的真实资料）、Q4 中的睡眠补跑与 Dots 并发、Q5（多日连续性）和 Q7（真实显示）需要真实用户环境与真实时间，由用户直接做端到端测试，本方案不另设真实时间测试。

## 每次运行记录一行

| 时间 | 触发 ID | due / pending | 资料来源（只写来源与一句摘要） | 决定 | 阶段 / 状态变化与依据 | 形象更新 | 输出位置 | 问题 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

不保存真实用户资料原文，只写 Agent 用了哪类来源、得到什么样的线索。记录留在本地 `$RUN`，不入库。

发现的问题对应到具体环节：宿主定时配置、`scheduling.md` 的运行说明、某个生成单元，或代码。

按轻量记录规则，仓库里只在 `docs/evidence/README.md` 追加几行摘要。
