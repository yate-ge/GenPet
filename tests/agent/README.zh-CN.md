# GenPet Agent 验收

本套验证生成语义、真实图像和宿主表现，完整用例以 [测试用例](CASES.zh-CN.md) 为准，产品原则见 [principles.md](../../plugins/genpet/skills/genpet/principles.md)。生成的故事、消息和领养结果和 [目标输出](targets/) 对照：[日常故事](targets/STORIES.zh-CN.md)、[领养旅程](targets/ADOPTION.zh-CN.md)，报告里把实际内容和目标输出并排写出。工程检查是 npm run verify:fast；字段有效、脚本通过或生成者自评都不能证明内容和桌面体验。

## 基本做法

- 只手写合成原始资料、用户旅程回答与规则探针。创作上游由 Agent 本轮生成并保存，作为冻结的下游输入；不规定标准角色、身体或故事答案。
- 上游与单元分开，生成者只拿 unit-request 的 prompt；独立 reviewer 拿实际输入/输出和检查点，写具体观察，不拿预期结论。按用户授权可用子代理；看语义不能只验 JSON。
- 单元、二十次模拟和工程测试使用独立 GENPET_DATA_DIR/CODEX_HOME，不读真实用户记忆、不改用户 Pet、不建真实任务。
- 真实宿主接口测试单独分层。读取真实配置不意味着隔离文件能连到真实客户端；只能操作专属测试 Pet 的已核对唯一/cloud ID、专属任务。用户正在养的 Pet 和任务保持原样。没有实际宿主证据的条目保持未验证。
- 已授权的开发工作继续执行，不逐段重问许可。测试里模拟真正领养用户的确认，必须保留确认前后读取和写入的证据。
- 原生生图保存工具提供的原 PNG、路径、字节 SHA 和小型计时元数据；不把大 base64 返回嵌入可执行代码或 shell 参数。raw 不完整记 partial/unknown，不从 PNG 重建；被工具或审批拒绝的载荷不分段、换 API 或换存法重传。计时回执本身有开销，性能对照需注明记录方式。
- 产出按下节「产出」整理在 `output/` 下；产物和报告都不入 git。

## 产出

每一轮测试在 `output/agent-tests/<版本>-<日期>/` 下整理出三样东西，同一轮的补测和重跑也放在这里：

- `REPORT.zh-CN.md`：本轮结论，每条用例写结果，并写出它的文件在哪。
- 每条用例一个文件夹（例如 `S24/`）。每个样本只放输入 `<样本>-input.json`、单元或流程结果 `<样本>-result.json`、用户看到的最终消息 `<样本>-message.md`（有的话）、独立评审 `<样本>-review.md`，加上结果里用到的最终图片。
- `raw.zip`：本轮其余过程打成一个压缩包，包括 Codex 会话和事件、stderr、记录快照、中间图和一次性脚本。

能重新生成的东西不用保留：隔离 CODEX_HOME 里装好的插件和缓存、`.pyc`、依赖目录。`auth.json` 用完就删，不进 `raw.zip`。

## 准备与一个单元

先检查当前工作区与已有构建，按需 npm run build:plugin；不要让测试自动 git pull/reset 覆盖开发改动。在 PowerShell 中建立独立 run：

```powershell
$agentRun = Join-Path (Get-Location) 'output/agent-tests/20261011-run1'
New-Item -ItemType Directory -Path $agentRun -Force | Out-Null
$agentCli = (Resolve-Path 'plugins/genpet/dist/cli.js').Path
```

1. 写绝对输入文件 `{"inputRefs":["fixture:A6"],"inputs":{...}}`，必需键见 units.json。context 包含测试提供的实际资料与 read 结果；random、journey、recentContent 采用保存的真实工具结果。
2. `node $agentCli unit-request UNIT ABS_INPUT_JSON`，保存精确返回 request 与 promptHash。
3. 把返回 prompt 给生成 Agent，仅执行这个单元，保存原始结果文件。独立图像任务保存其所有中间图，不在主对话显示候选。
4. `node $agentCli verify-unit UNIT ABS_RESULT_JSON` 保存格式结果；再由独立 reviewer 检查语义，观察指向具体事实、选择、部位或文字。
5. 下游只引用已经保存的上游结果。基准图测试实际调用 imagegen 并实际看图；ImageReviewer 没有真实文件不能通过。

独立单元用固定输入，不需要完成整个生命周期。runtime record-step 保存简短结果供实际故事续接；精确请求、原始输出和独立评价属于测试 evidence。

## 逐组执行

A 组保存首次资料说明/答复、读取记录、每轮场景/选项/用户原话、旅程结束、种子候选/选择、具体来源与 designReason、性格和拟声词、蛋图与总结。验证最多五轮、自由回答、中断续接、资料稀少仍有真实选择依据、敏感资料不流入下游、总结不透露幼年身体。实际读取成功独立核对，文件存在不是证明。

T 组各连续二十次，用固定/逐次提供的合成 context 和真实保存的上篇结果继续。每次的输入里有用户此刻的情境：用 [sessions/make-sessions.mjs](sessions/make-sessions.mjs) 在隔离 `CODEX_HOME` 放合成会话（在忙、有节点、平常、开着几天没用、关了再打开、名称看不出主题、生活里的事、写作、英文、几件事混在一起、同一种状态连续几天及其对照、恐怖题材、低落情绪、名称含敏感内容、GenPet 自己的定时任务会话；案例和提示词里的例子只是方向，测试情境另编，按原则判断，并统计示例照搬，见用例 T15），由 Agent 自己找到并读取，保存它写下的那几条观察和来源；不要直接把情境写进输入替 Agent 判断。每次由 story 单元按情境直接决定怎样回应（0.10.13 起故事不再列候选、不用种子），记录它回应的是哪条情境或对话，再 evolution/appearance/home/story-item，写出预期可见变化与 output 的最终消息。模拟尚未画图必须标为计划，不能填写已上传/实际显示成功。评用户可见文字时用幼年/少年、按真实间隔连续，output 拿到实际接受的图，让图承担它该承担的部分；蛋期只看孵化前那一次，不连跑蛋期来评文字。保留每次是否重写 memory、经历数内部轨迹、成长/预兆、未完事项和类型变化。T8 的多样性是观察，不新增四次上限；最短两天不是成长规则。唯一类型硬上限是已有纯文字规则。

S 组使用独立规则探针：context 与文本原意、安全过滤、每次内容、弱交互、阶段/幻化、复用、用户可见文字、任务命名/补跑、许可、孵化命名、一次图片展示和成长图，以及看得懂和以用户为中心（S24、S30）、观察的读取与保存（S25）、消息格式（S26）、虚拟世界与说的话（S27）、用户自己说的心情（S31）、成长没到期时不成长（S32）。S26 的格式可以用脚本查 output 的 message：有图时图在最前，写成 `![说明](<绝对路径>)`、文件存在、说明用消息的语言，叙述和说的话至少有一样，有叙述时是单独一段斜体，有说的话时是单独一段「**名字**：话」，名字与 story-output 的 name 一致、未起名时用「它」；内容由人看。不要把「每次有内容」变成强制状态修改。文本-only 有实际用户相关 contextRefs；物件为 null 并不表示 text-only，还可能有 Avatar/家。

V 组四条分别使用自己的测试 Pet，互不交叉。V1 至少六份不同用户资料并覆盖工具的三类来源，各只到幼年；V2 一条蛋→幼年→少年→成年；V3 成年幻化：以用户连续几天的同一种状态为契机进入、两天内结束、隔一周后再次幻化并复用，同时看安全护栏；V4 至少三次不同日常样子并复现一次，其中一套是休息或专注做事，看每个动作槽位是否按这个状态设计（S29）。每次真画完整套、检查小尺寸、计时与云图回读；静态基准只能证明基准。身体左右不对称的镜像需单独看，返工/补帧也看实际整套。用户对可爱、身份、阶段与设计联系的判断不可代填。

C/E/G/U 按完整用例逐项运行，使用 /genpet-chat 唯一对话入口、/genpet 命名与故障。对比 ID、cloud ID、soul/memory/state/art/history；故障不能重领养、推进年龄或重画。四项结果分别记录 unknown/actual，刷新或选择读回不是显示证明。

D/M 先读-only 能力探查与基础测试，再用专属测试 Pet 验证云图、简介同步、持久语气、唯一主环境和每只独立目录。主环境移交已于 2026-10-15 暂时收起（未经真实宿主验证），相关用例暂停。Dots 不使用已移除的独立包或 Avatar 格式。

每一轮的范围、生图预算和授权项写在那一轮的报告开头。

## 额外缺口与恢复用例

同时验证实际资料读取、五小时任务、旧导入中断重试、来源种子重试、memory 不重复计数、云上传未发生时 pending、成长基准图失败、补帧观感。多 Pet 分别覆盖：A 切走十天再回来（期限暂停），A 激活时关机十天（时间经过），故事中途改选 B（仍写原 A）。这些不是额外创作预设，是工程边界。

真实宿主的任务循环见 [SCHEDULED_LOOP](SCHEDULED_LOOP.zh-CN.md)。报告用 [REPORT_TEMPLATE](REPORT_TEMPLATE.zh-CN.md)，每项写通过/需修正/未验证与具体证据和文件路径；最终用户体验判断留给用户，缺证据不能标通过。

## 从运行时说明移来的验收要求

以下内容是开发验收的要求，不放在插件的运行时说明里，因为真正养宠物的 Agent 不需要读。

- 资料读取：开发与宿主测试保存读取时间、来源引用、成功/失败和采用事实 ID，核对故事或旅程是否真的用了那条资料。目录存在、文件日期更新、prompt 写了「结合记忆」都不能证明实际读取。测试只保存合成资料；真实测试记录只写安全摘要与来源种类。
- 定时内容：「当天至少一次可见变化」需要真实宿主记录证明，协议测试不能支持这个结论。
- Dots（D 组）：先在专属测试 Pet 上验证宿主能力；用同一组工作请求对照三个阶段和无 Pet，核对工作内容不受宠物语气影响；保存完整安装过程、确认次数和新会话结果；D6–D11 需要跨端回读、全新会话和工作对照，本地文件证明不了持续生效与主动联动。
- 生图与审核：ImageReviewer 必须接收实际图像，没有文件即未通过；基准出图测试实际调用图像工具，保存请求、参考与返回图；完整 Avatar 的 V 用例另外生成整套并验证宿主，不用静态基准证明整套成功。
- 子代理媒体：测试时实测子代理生成的图是否仍显示在主对话。
- 真实宿主验证用专属测试 Pet 与 cloud ID，不接管用户正在养的那只。
