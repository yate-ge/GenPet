# 实际读取用户资料

此流程由 GeneDesigner 和 StoryDesigner 共用。规则见 ../rules.md「用户资料与安全」「用户联系」。它先获取实际输入，再运行 context 单元。

## 读取顺序

1. 第一次领养前查看主 skill 的许可步骤。尚未同意时，先给直接简短的说明并等明确答复；不读用户资料、不分配领养记录。已有 Pet 的已确认许可沿用。
2. 根据宿主实际提供的工具、自动加载的上下文与配置，确认有哪些用户记忆来源。优先宿主已经整理的记忆。文件路径从当前环境的实际配置/目录确认，工具名称从可用工具确认，不把某台机器的路径或格式写死在代码中，也不扫描无关个人目录。
3. 真正读取当前需要的片段：从简短摘要开始，只有相关内容不足时才定位对应原记录。观察范围由此次用途决定；旅程选择、用户对宠物的话、已有故事与 time 也可提供真实输入。自动提供的资料必须已经在当次上下文中，只有看到工具或文件名不算读过。
4. 用 context 单元提炼安全的 facts、traits、unknowns、read。每条事实给出可定位的来源：工具结果引用、文件与小节、旅程轮次或聊天记录 ID。愿望、提问、一次性选择与纠正保持原意；敏感内容在进入结果文件前过滤。
5. 保存简短结果到 record-step；下游引用其 step ID 与 facts ID。内部只保留必要的摘要和出处，不保存整份宿主记忆。

read.status 为 success、unavailable 或 failed。success 的 facts 可以为空；unavailable 表示宿主没有可用记忆接口/数据，failed 表示尝试读取但失败，简短记录原因。不能把 failed 写成「用户没有新变化」。

## 观察用户此刻的情境

每次故事都要知道用户此刻的情境：在不在、忙不忙、大概在忙什么、多久没来了。这来自最近的会话，Codex 记忆说明的是用户是谁，不是此刻。

- 会话记录在哪里、什么格式，由 Agent 在当前环境里自己确认，不假定固定路径。
- 由浅到深读，每一步判断够不够：先看会话的名称、项目和开始/最后活动时间；看不出在忙什么时，读会话里用户的第一条消息；还不够再往后读。读多少由需要决定，够这次故事判断就停。
- 用户自己的消息最能说明用户在做什么；助手回复、工具输出和文件内容一般用不上，也不需要知道用户具体写了什么。
- 时间范围按需要：平常从上次故事起，必要时看到当天；很久没来时知道最后一次活动是什么时候就够了。
- 排除 GenPet 自己的定时任务会话和宠物对话。
- 结果在 context 里写成一条简短的情境事实，例如「今晚 10 点后一直在同一个项目里」，source 写会话 ID 与时间；不保存会话名称原文和用户消息。会话名称本身也可能敏感，按安全规则过滤。
- 找不到或读不了时记为 unavailable 或 failed，不当成用户不在。

## 资料不足时

没有宿主记忆时，使用这只 Pet 已保存的真实旅程、对话和故事来源，并参考最近一次 context 单元中的简短了解。新真实来源出现时由 Agent 重写当前的简短了解，不从没有输入推导喜好。不要在能读宿主记忆的环境另外保存长期用户画像。

领养资料稀少时从领养当下生成奇遇，由用户真实选择补充理解；已有宠物仍有旅程线头、家、物件、自己的活动和时间可写。无法形成用户相关 context 时选择有可见变化的故事，不生成无依据的纯文字。
