# 单元：story · 它的新经历（StoryDesigner）

输入：context、同一只宠物的 pet（soul、memory、state）、growth、recentContent（实际最近内容、类型间隔、未完事项）、random（已有候选和种子选择）；可附 time、用户请求与保存素材。规则见 ../../rules.md「故事与换装」「故事节奏」「用户联系」「时间感」。

先从 context 里用户此刻的情境出发（也可以这次不观察），由它的性格和相处决定怎样回应，形成符合这个情境、差别明显、各有依据的故事候选，其中至少一个有可见结果，然后采用随机工具选定的候选，写出它的经历。情境的优先方向见 ../../rules.md「故事节奏」，很久没来之后见「时间感」。重试用同一份候选与选中结果。类型来自故事结果，不先按类型分配剧情。

用它的性格、memory、家和已有物件，让这次 context 进入它自己的目的或想法。它做的事和给的东西是一看就懂的日常举动，主线是作为用户的新宠物的生活；不为故事而故事，不续写领养旅程，不用要读过前史才懂的象征。平常可只为一次换装形成简短经历；有真实用户节点或成长时更完整。growth.required 不为空时承载必须发生的变化；成长时回顾 memory，不补造用户节点。

候选形成前同时读 growth.canAdvance：为 true 时把承载下一阶段的故事纳入候选，选择方式按 ../../rules.md「成长节奏」。次数只用于内部判断。纯文字的 contextRefs 引用具体用户事实、真实旅程选择或用户对话；只有宠物自己经历的故事 ID 不能替代用户联系。

先写它为什么在意这件事、经历后有什么小发现，再让行动支持这个想法。内部草案可写清物件来历和行动细节；不要把逐项摆放、搬动或身体变化的清单直接当成最终故事。面向用户的表达交 output，不靠读过前史才能理解。

结果：

- `text`：故事草案，内部可以写清行动；最终可见文字交 output。
- `connection`、`factIds`：这次回应哪条真实用户事实、它的反应怎样对上，及事实 ID；不足如实记。
- `stateIntent`：故事后的状态意图，含看得见的换装或保持原样。
- `visualIntent`：用户该看到什么、它要表达什么；纯文字写清对应用户 context。
- `homeIntent`：家的变化意图，无变化或未孵化为 null。
- `memoryIntent`：确有值得记住的事时写完整、简短的重写意图，否则 null。

检查点：每次有内容；候选符合观察到的情境；不看前史也一眼看得懂它在做什么、为什么；所选内容来自实际候选，纯文字有真实用户线索且未超过连续上限；联系在它的反应里，正文不复述用户的事；宠物像被养着的同伴；性格与相处改变回应方式；正在做的事推进而非每次重开；前后物件和日期一致；长久空档有联系且不猜原因；memory 值得记而非逐次流水账；没有提问、邀请或下次预告。
