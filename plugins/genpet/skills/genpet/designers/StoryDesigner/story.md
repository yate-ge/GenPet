# 单元：story · 它的新经历（StoryDesigner）

输入：context（含用户此刻的情境）、同一只宠物的 pet（soul、memory、state）、growth、time（begin-story 返回的距上次故事多久等）、recentContent（实际最近内容、类型间隔、未完事项）；可附用户请求与保存素材。需要旧物、以前的样子或家时，按需要自己查：status 的 art 列出已接受的图（类型、阶段、描述和文件），memory 里注的图 ID 和以往故事也能找到，必要时看图本身；用不上就不查。规则见 ../../rules.md「故事与日常」「故事节奏」「用户联系」「时间感」。

先从 context 里用户此刻在做什么出发，由它的性格和相处直接决定怎样回应，选最能回应这个情境的做法，对照 recentContent 让做法、主题和形式与最近不同，写出它的经历。情境的优先方向见 ../../rules.md「故事节奏」，很久没来之后见「时间感」。context 里有用户在上一次故事之后的对话中留下的话时，这次按 ../../rules.md「性格与对话」回应它。重试沿用已保存的结果。类型来自故事结果，不先按类型分配剧情。

用它的性格、memory、家和已有物件决定怎样回应用户这件事：对用户说话、为用户做或给一样东西，或在一旁陪着用户做；用户一读就该知道它在回应自己。只有用户不在时（很久没来、读不到会话）才讲它自己在做什么。它做的事和给的东西是一看就懂的日常举动，故事的主角是用户和它的相处；不为故事而故事，不续写领养旅程，不用要读过前史才懂的象征。平常可只为一次日常变化形成简短经历；有真实用户节点或成长时更完整。growth.required 不为空时承载必须发生的变化；成长时回顾 memory，不补造用户节点。

同时读 growth.canAdvance：为 true 时按 ../../rules.md「成长节奏」判断这次是否承载下一阶段。次数只用于内部判断。纯文字的 contextRefs 引用具体用户事实、真实旅程选择或用户对话；只有宠物自己经历的故事 ID 不能替代用户联系。

讲法随这件事走，不必每次都有理由、尝试和小发现；对照 recentContent，换一种回应用户的方式。内部草案可写清物件来历和行动细节；不要把逐项摆放、搬动或身体变化的清单直接当成最终故事。面向用户的表达交 output，不靠读过前史才能理解。

结果：

- `text`：故事草案，内部可以写清行动；最终可见文字交 output。
- `connection`、`factIds`：这次回应哪条真实用户事实、它的反应怎样对上，及事实 ID；不足如实记。
- `stateIntent`：故事后的状态意图，含看得见的日常变化或保持原样。
- `visualIntent`：用户该看到什么、它要表达什么；纯文字写清对应用户 context。
- `homeIntent`：家的变化意图，无变化或未孵化为 null。
- `memoryIntent`：有值得记住的事（见 ../../rules.md「soul 与 memory」）时写完整、简短的重写意图，否则 null。

检查点：每次有内容；回应符合观察到的情境，对话留下的话得到回应；不看前史也一眼看得懂它在做什么、为什么；纯文字有真实用户线索且未超过连续上限；用户不看内部记录也认得出它在回应自己，没有另起一条它自己的生活线；它做的事和给的东西都在它自己的世界里，没有假装替用户做了现实里的事；宠物像被养着的同伴；性格与相处改变回应方式；跟着用户的事推进而非每次重开；前后物件和日期一致；很久没来时按 ../../rules.md「时间感」外出、修家或回来，不猜原因；memory 值得记而非逐次流水账；没有提问、邀请或下次预告。
