# 单元：appearance · 宠物形象（PetDesigner）

输入：genes、已形成的 story、change、savedArt、实际 hostRequirements；可附同阶段已接受形象和预生成成长图。遵循 ../../rules.md 的设计、阶段、日常、幻化、动作表达与检查规则。

为初始化、阶段成长、幻化或日常变化形成 Avatar 请求，合适的已有图直接复用。进入不同阶段时发展身体和能力；结束幻化时复用幻化前的日常样子图；日常变化保持同阶段身体，整套动作与方向呈现一致。没有形象变化时 appearance 为 null。故事物件和家的图由各自单元设计。

成长先说明这只身体的主要结构怎样从未展开、部分发育走向成熟，再把变化画进轮廓、器官和它能做的动作里；并列缩小后仍能读出成熟度，不靠放大、换色或轻调耳尾支撑成长结论。相邻阶段先看最能表达发育的一处主要结构，幼年收拢或未展开，少年实际展开并开始使用，成年完整；身份核心保持，不能让幼年先长齐再只微调少年。幻化先写明幻化对象，再写它的哪些特点和这只宠物的哪些身份核心结合；轮廓、构造或质感要有大变化，一眼认得出是它变的。换衣、拿物或轻换姿势不能代替幻化。变化的具体形式来自这只 Pet 的基因和故事，不规定统一比例或器官组合。

日常变化常是它对用户此刻情境的反应，例如用户备考时它戴上眼镜抱书苦读，用户很久没来时它戴草帽拖着行李箱出门；一眼看得懂它在做什么。保持身体身份不等于固定姿势。依据这次故事里正在做的事，让体态、目光、重心与衣物或道具的接触一起变化；看得出它在穿、拿或使用，而不是给同一张摆拍像加东西。动作适合已有器官和阶段，支撑自然，不添新肢体。

请求里先为每个动作槽位写出这次的样子下它怎样回应，再画，按 ../../rules.md「动作表达」：休息中的宠物左右槽位可以是转头看、翻身，点击可以是伸懒腰，不必站起来走跳。

角色穿戴由故事活动决定衣型、材料和接触方式，类别差别要体现在实际衣物与动作中，而不只靠名称或一顶帽子。让衣服适合原有身体，识别结构仍能看见；不同身体用自己的器官完成角色活动，不画成共用的人类身体。

参考图只来自这只宠物的已接受图。首次孵化的蛋仅提供壳面线索，身体来自 genes；后续延续已孵化身体。否决候选用于说明修正，不作为身份参考。请求写清轮廓、色块、结构、阶段与故事变化，不只附风格词。

新图请求明确使用平坦像素色块与硬边阶梯明暗，身体内部不加连续渐变、细颗粒或材质晕染；只有像素外轮廓不算符合。在实际显示尺寸判断有意义的风格差别，不放大不显眼的边缘像素反复润色。

结果：`appearance` 为 `{description, reuseArtId?}` 或 null；`visuals` 为请求列表，每项说明用途、描述、request、references、mustShow 与 hostRequirements，复用项写实际 file/artId。新整套图采用当前宿主要求的透明 atlas，同一个 cloud ID 在两边使用同一份已接受的图。

检查点：去掉穿戴仍是同一身体；幼年没长开且至少有眼睛；变化在实际尺寸可读；新的日常样子覆盖整套，每个槽位的动作符合这次的状态；幻化有明确的对象、大变化且认得出是它，没有越过安全护栏；复用图属于该 Pet 并匹配阶段、幻化与状态；pre-generated 图的阶段依据仍适合本次故事；实际格式来自宿主要求。
