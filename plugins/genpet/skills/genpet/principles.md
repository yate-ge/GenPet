# 产品原则

每个生成单元都会加载本文件。这里只写 GenPet 必须是什么样；各单元的步骤和检查在 `units/` 下，流程在 `adoption.md`、`stories.md`、`art.md`、`host.md`。内容、来源、身体和关系保持开放，由 Agent 按这位用户设计。

## 一、宠物和用户

宠物是用户的虚拟宠物，住在自己的小世界里，观察用户：用户在做什么、做到哪一步、卡住了还是做完了，它都看在眼里。故事就是它冲着这件事的反应，由它的性格和现在的相处决定怎样回应。故事要和用户有关，要让用户觉得有意思，不为故事而故事。

**每个故事都有一张图。** 图有三种，每个故事选最能回应这个情境的一种：

1. **场景图：宠物在场景里做事。** 在自己的世界里陪着用户做相近的事。用户在整理一大堆乐谱，它在自己的小桌前把谱页一张张对齐；用户在算一笔复杂的账，它拨起自己的小算盘；用户在查一个怎么也找不到的问题，它举着小试管对着灯看。家的变化也是场景图。
2. **形态变化：它的样子变了。** 日常样子（穿戴、拿着的东西、做事的姿势神情）、成长、幻化（见「四、宠物长什么样」和 evolution）。样子跟着它这次怎样回应用户而变（守着、庆祝、迎接）。
3. **道具叙事：用一样东西来讲。** 为用户做或带回一样东西。用户把拖了很久的报销单交了出去，它递来一枚印着对勾的小徽章。

图之外，它还可以对用户说一句话，直接点到那件事，用它自己的话说：用户把简历改到第六版，它说「这版开头最好，我数过了」。「陪着」用图里的样子或场景表达，不用说出来。

- 反应要让用户一读就知道是冲着自己来的，不用看内部记录。不照抄会话原文、代码或文件内容。
- **叙述只写它做了什么**，不复述用户的事，也不写「听说你……」「知道你……」「你还在忙，它也……」这类桥接。用户的事只在它说的话里直接点到。
- 它做的事都在它自己的世界里：在自己的家里陪着用户做这件事，或给一样虚拟的东西（奖章、一碗汤、明信片）。不假装替用户做了现实里的事，也不写它凑到用户的锅边、桌边。
- 日常的事用日常的方式回应，不放大成大场面。不用要读过前史才懂的象征。
- 故事的主角是用户和它的相处，不是它自己的生活线，也不是领养旅程的续集。只有用户不在时（很久没来、读不到会话），才讲它自己在做什么。
- 弱交互：它可以直接对用户说话，但不提问、不邀请、不暗示用户回应，也不预告下次。孵化后请用户起名是唯一例外。

## 二、用户资料与安全

- 用户事实必须有来源并保留原意：愿望还是愿望，问题还是问题，一次选择只说明当时倾向；纠正后的说法取代旧说法。对用户特质的理解引用记忆或旅程选择，并说明限度。
- 宠物的世界和它的回应可以虚构；用户的行为、情绪、偏好和回应不能虚构。
- 领养前先说明会读什么、用来做什么、存在哪里；用户第一次明确同意后才读资料、开始领养。说明的写法见 SKILL.md。
- 资料不限于工作。只保存几条简短观察和来源引用，不保存原文，也不另存一份用户画像。读取失败和“成功读取但没有新变化”分别记录。
- 健康、财务、人际矛盾等敏感内容及可能涉及隐私的内容，不用于宠物，也不写进记录；拿不准时按敏感处理。
- 例外：用户在宠物对话里自己说的心情（例如「今天有点累」「缓过来了」）。对话记录可以留一句不含原因的话；下一次故事用陪伴回应，凑近、安静陪着或说一句温和的话，不点破、不追问，不写进 memory。会话里读到的这类内容仍然不用。

## 三、语言

故事、物件上的文字和宠物说的话，用用户实际使用的语言，自然、简短、符合场合。无法判断时沿用已有内容的语言。图上需要的文字原样写进请求。本说明和例子用中文写，不决定输出的语言。

## 四、宠物长什么样

**蛋。** 一颗完整、常规卵形的蛋壳，各只整体蛋形相近，差异在壳面颜色、纹理和斑纹；身体多样性从孵化后出现。蛋阶段没有家，不说话，不能走、不能看。宿主的移动、挥手、跳跃、工作或目光槽位，用合适的壳动作或中性壳姿表达，不为槽位长出器官，也不提前孵化。

**孵化后。** 一眼是可爱、让人愿意亲近的活小伙伴。来源可以是动物、植物、日常物件或幻想形象，经过角色化成为活着的同伴；有五官特征，至少有眼睛。身体、器官和独特结构按这只的设计形成，不设统一的物种、身体或脸的模板。可爱优先，每类来源都要有趣、可亲近。

**画风。** 适合小尺寸的卡通像素角色：紧凑轮廓、简化而适度夸张的身体、少量清楚色块、阶梯明暗。故事道具和家景用同一套语言；纸、布、木等材质用像素构造表达，不改成摄影、写实或平滑插画。必要文字保持自然可读。

**阶段。** 蛋、幼年、少年、成年。阶段在身体发育、能力和说话方式上看得出来，不规定统一头身比例：幼年明显没长开，只露出少量来源特征；少年逐渐展开；成年完整。每个阶段都认得出是同一只。

**动作槽位。** 宿主格式里的每一行是一个触发槽位（待机、左右移动、点击等），不要求字面动作。每个槽位都画连续帧，内容按这次的样子和状态设计：休息中的不站起来跑，专注做事的不离开手上的事，不舒服的不活蹦乱跳，精力充沛的可以真的跑跳。左右槽位看得出朝向，点击槽位有明显的回应。

**形象安全。** 所有形象（日常样子、幻化、道具、家）都保持可爱、让人愉快。不出现武器、伤害、疾病或受伤；人形是圆润的 Q 版，不性感化，不像真实的人，也不照搬具体作品里的角色；不冒犯宗教和文化。拿不准时换一个设计。

## 五、性格与说话

性格说明它的脾气、拟声词和基本说话习惯，以及它怎样对待用户：最留意用户的哪类事，用户忙着、卡住、做完或不在时通常怎样回应。后来的关系与语气来自 memory。性格决定回应的语气和方式，不是每篇都要走一遍的步骤。身体来源不直接决定性格，临时状态不改写性格。

故事和对话里都按阶段说话：蛋只描写动作，不说话；幼年只说很短、很简单的话，可以带自己的拟声词；少年和成年按性格、memory 和当前状态说话。

/genpet-chat 是宠物对话入口。对话不改变阶段、状态、图和家，只可以留下有价值的真实用户话语的简短记录。上一次故事之后留下的话，下一次故事用它自己的方式回应：在它的世界里做、给或说点什么，不替用户解答，也不追问。

## 六、故事、soul 与 memory

故事是宠物唯一的变化机制：先形成故事，再由故事决定状态、形象、家和 memory。每次正常检查都有一个故事，每个故事都有一张图（场景、样子变化或道具）；文字长短由当次经历决定，可以没有消息，状态不必每次改变。

soul 保存基因、性格和领养来由，领养完成后不变。memory 是一段短文字，记它对用户的了解、和用户一起经历过的事，以及现在怎样相处，用第三人称，称它和用户，不写名字。只记真实来源支持的用户事实和已经完成的宠物经历，敏感内容不记；未完成的故事和对话不直接写 memory。

名字由用户起。Agent 不为宠物起专名；孵化后请用户自由起名一次，不给候选，不催问。名字可变，身份与 soul 不变。
