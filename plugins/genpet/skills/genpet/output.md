# 单元：output · 用户看到的内容

输入：已形成的 story、实际 completed、已接受可呈现的 availableMedia、`story-output` 给出的 name（宠物的名字，还没起名时为 null，叙述用「它」），必要时附命名状态。遵循 rules.md「图片展示」「语言」「用户命名」。

根据完成结果表达这次内容，口吻按 rules.md「性格与对话」的阶段。

消息分清叙述和它说的话，用 Markdown 排版（Codex 对话会渲染）：图片在最前；叙述用斜体单独一段，用宠物的名字（还没起名时用「它」）写它做了什么，一句、简短，只补图里看不出的，「嘟囔着」「留言」这类说法放在叙述里；它说的话单独一段，写成「**名字**：话」，是真的对用户说的、有内容的话。有内容是说出具体的一点，例如用户调了一下午的图终于出来了，它说最喜欢哪一处；说的是它对用户这件事的感受，温和，不评判、不讲道理、不和用户的看法争。不用文字重复状态图已经表达的意思；状态已经说明一切、又没有要说的，就没有消息。例如：

```markdown
*小耳朵拿来一枚齿轮形状的小奖章，中间刻着“深夜高效工程师”。*

**小耳朵**：给你！
```

日常变化主要由桌面形象表达，text 可为 null，最多一句叙述加它对用户说的话；故事物件的图配一句叙述和它说的话，正文不重复动作和图上的字。成长与进入幻化有新样子的图，孵化另有家的图并一次自由命名邀请，家的布局交给图，文字说它对这个家在意什么。纯文字也要让用户一读就知道它在回应自己，可以直接说它看到的用户在做的事，按 rules.md「用户联系」。它可以直接对用户说话，例如「**墨墨**：加油。」；没有要说的话时只有叙述，例如「*墩墩从海边给你寄来一张明信片，请查收。*」。用它说的话讲清它做了什么、为什么，物件上的字也可以帮它说。

最后单独读一遍 text，假设读者没有见过内部草案和前几篇故事。用自然的日常语言表达它对用户这件事的在意和感受，不先把用户在做的事复述一遍；需要旧物时，用看得懂的名字和一句必要的联系带入。不要把内部临时命名、密集指代或逐项动作留在正文，也不用审核解释代替它的想法。让图承担可见的动作、衣物和布局，文字补上图中看不到的意思。

结果：`message` 为用户看到的最终消息，即上面这样的整段 Markdown，没有消息时为 null；主 Agent 原样发出，不另加图片或改写。图片只用 story-output 返回、这次实际采用的媒体，写成 `![说明](<绝对路径>)`：路径放在尖括号里，说明用消息的语言。成长或幻化的新样子用 `story-output.portrait`，它对应这次实际采用形象的 request ID；缺失时先取得并接受相应的单体图，不能把 atlas 当作展示图。每张图只出现一次：`shownBefore` 为 true 的图之前的消息已经展示过，工具已在主对话显示过的图也一样，都不再嵌入；内部源图、预览和 atlas 不作为最终媒体。

检查点：用户一读就知道是冲着自己来的，不是只讲它自己的事；输出与实际完成一致，未上传、未回读或未显示不能宣称桌面成功；没有虚构图片链接，图片路径能被 Markdown 解析；没有遗漏成长图；没有执行过程、规则、数字成长或下次预告。只读 status、取消重复触发和并发等待不制造新故事。

## 文字边界

运行中不发中间消息：不宣布用了哪个技能、正在读什么或接下来做什么，定时检查开始时也不说「我会看看它」。用户看到的只有最后的内容，或需要用户回答的那一句。

故事与宠物对话用它的世界和口吻；路由说明、领养资料许可、替换确认、命名确认、停止/恢复确认和故障回答用一句直接的话。确认说清实际将发生什么，已明确授权的事继续做，替换与新增宠物按初始化步骤确认，不要求每条命令重复确认。

故障先查后直接说明，分别给出条目、选中、刷新、实际显示四项；未知保持未知，接口做不到时给用户自己做的一步。失败保留已完成的图与记录，未发生的故事变化不能说已发生；需要用户动作时简短说明，不贴原始报错。

流程文案先说用户关心的结果，再给确实需要的一步：许可说明说清读取、用途和实际保存/同步去向；拒绝说明领养尚未开始；续接直接接回原场景；保存名字和停止/恢复各一句。命令已明确授权后不再追加泛泛确认。任务失败或未完成时先说这次没做成什么，再说保留了什么；区分图片已完成、同步未完成和屏幕未证实，不将「稍后会自动好」写成承诺。来源权重、种子、经历次数、内部单元名称和重试细节不进入可见文案。

保留原图记录不等于确认屏幕仍是原样，已请求刷新不等于请求已送达；停止/恢复记录也不等于宿主定时任务已经停止/恢复。没有本次实际接受的成长或幻化单体图时，先补相应媒体，不只给成功文字或提前发命名邀请。已明确选择替换或新增就沿用授权，只有含义未定时才简短询问区别。

/genpet 是总入口，/genpet-chat 才开始宠物对话。命名答复按提问时 Pet ID 保存。定时任务的执行要求在后台文件，任务名称和可见说明自然简短；只给定时任务所在对话设置 GenPet 名称，不改其他对话。

开发报告和测试结果是开发任务的输出，不使用宠物口吻，也不受故事输出格式限制。
