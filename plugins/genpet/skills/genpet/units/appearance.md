# 单元：appearance · 宠物形象

输入：genes、已形成的 story、change、savedArt、实际 hostRequirements；可附同阶段已接受的形象和预生成的成长图。

## 做什么

为初始化、阶段成长、幻化或日常变化形成 Avatar 请求；合适的已有图直接复用。故事物件和家的图由各自的单元设计。没有形象变化时 appearance 为 null。

- 进入不同阶段时发展身体和能力。
- 日常变化保持同阶段的身体，整套动作和方向一致。
- 结束幻化时复用幻化前的日常样子图。

**参考图只来自这只宠物已接受的图。** 首次孵化时，蛋只提供壳面线索，身体来自 genes；之后延续已孵化的身体。被否决的候选用来说明修正，不作为身份参考。请求写清轮廓、色块、结构、阶段和故事变化，不只附风格词。

**像素要求。** 新图请求明确使用平坦的像素色块和硬边的阶梯明暗，身体内部不加连续渐变、细颗粒或材质晕染；只有像素外轮廓不算符合。在实际显示尺寸下判断有意义的风格差别，不放大不显眼的边缘像素反复润色。

### 成长

先说明这只身体的主要结构怎样从未展开、部分发育走向成熟，再把变化画进轮廓、器官和它能做的动作里。并列缩小后仍能读出成熟度，不靠放大、换色或轻调耳尾支撑成长。相邻阶段先看最能表达发育的一处主要结构：幼年收拢或未展开，少年实际展开并开始使用，成年完整。身份核心保持；不能让幼年先长齐、少年只微调。具体形式来自这只的基因和故事，不规定统一比例或器官组合。

### 幻化

先写明幻化对象，再写它的哪些特点和这只宠物的哪些身份核心结合。轮廓、构造或质感要有大变化，一眼认得出是它变的。换衣、拿物或轻换姿势不能代替幻化。规则见 evolution，安全边界见 principles.md「形象安全」。

### 日常样子

日常变化常是它对用户此刻情境的反应：用户在写一份长报告，它戴上眼镜抱着书；用户很久没来，它戴草帽拖着行李箱出门。一眼看得懂它在做什么。

- 保持身体身份不等于固定姿势。依据这次故事里正在做的事，让体态、目光、重心和衣物或道具的接触一起变化；看得出它在穿、拿或使用，而不是给同一张摆拍像加东西。
- 动作适合已有器官和阶段，支撑自然，不添新肢体。不同身体用自己的器官完成角色活动，不画成共用的人类身体。
- 角色穿戴由故事活动决定衣型、材料和接触方式，类别差别体现在实际衣物和动作里，不只靠名称或一顶帽子。衣服适合原有身体，识别结构仍能看见。

### 动作槽位

请求里先为每个槽位写出这次的样子下它怎样回应，再画（槽位的含义见 principles.md「四、宠物长什么样」）。例：休息中的宠物，左右槽位可以是转头看、翻身，点击槽位可以是伸懒腰，不必站起来走跳；幻化得来的能力可以用在动作里。具体动作按这只宠物的身体、阶段和状态决定，不固定动作表。

## 结果

- `appearance`：`{description, reuseArtId?}` 或 null。
- `visuals`：请求列表，每项说明用途、描述、request、references、mustShow 和 hostRequirements；复用项写实际的 file/artId。新的整套图采用当前宿主要求的透明 atlas，同一个 cloud ID 在两边使用同一份已接受的图。

## 检查

- 去掉穿戴仍是同一个身体；幼年没长开，且至少有眼睛。
- 变化在实际尺寸下可读。
- 新的日常样子覆盖整套，每个槽位的动作符合这次的状态。
- 幻化有明确的对象和大变化，认得出是它，没有越过安全边界。
- 复用的图属于该 Pet，并匹配阶段、幻化和状态；预生成图的阶段依据仍适合本次故事。
- 实际格式来自宿主要求。
