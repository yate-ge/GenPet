# 单元：context · 用户资料

输入：`availableContext`，包含本次真实读到的资料、读取结果、当前请求，以及宠物记录中的相关旅程、对话、历史、时间。领养和每次故事都先实际读取，再运行本单元。第一次领养要先完成 SKILL.md 里的说明和同意，同意前不读资料。

## 怎么读

1. 确认有哪些用户记忆来源：从宿主实际提供的工具、自动加载的上下文和配置确认，优先宿主已整理的记忆。路径从当前环境的配置和目录确认，工具名从可用工具确认，不写死某台机器的路径或格式，不扫描无关的个人目录。
2. 真正读取当前需要的片段：从简短摘要开始，相关内容不足时才看原记录。旅程选择、用户对宠物说的话、已有故事和 time 也是真实输入。自动提供的资料必须已在当次上下文里；只看到工具名或文件名不算读过。
3. Codex 记忆说明用户是谁，用于领养和成长；活动用于故事和对话。
4. 提炼出安全的 facts、traits、unknowns、read，每条事实给出能定位的来源：工具结果引用、文件与小节、旅程轮次或聊天记录 ID。敏感内容在写入结果文件前过滤。
5. 用 record-step 保存这份简短结果，下游引用它的 step ID 和 facts ID。不保存整份宿主记忆。

## 观察用户此刻的情境

每次故事都要知道用户此刻的情境：在不在、忙不忙、在忙什么、做到哪一步（卡住了还是做完了）、多久没来了。这来自最近的会话。

- 会话记录的位置和格式由 Agent 在当前环境里确认，不假定固定路径。
- 由浅到深读，每一步判断够不够：先看会话的名称、项目和开始/最后活动时间；看不出在忙什么、做到哪一步，就读用户最近的几条消息；还不够再往前。够这次判断就停。
- 用户自己的消息最能说明他在做什么；助手回复、工具输出和文件内容一般用不上。不需要抄下用户写的原文。
- 时间范围：平常从上次故事起，必要时看到当天；很久没来时，知道最后一次活动是什么时候就够了。
- 排除 GenPet 自己的定时任务会话和宠物对话。
- 写成几条简短的情境事实，用自己的话说清用户在做什么、进行到哪一步、卡住了还是做完了，source 写会话 ID 与时间。例：「下午一直在调一个图表的坐标轴，换了两种刻度还是挤在一起」「昨天晚上之后没有新会话」。不保存会话名称原文和用户消息原文；会话名称本身也可能敏感，按安全规则过滤。
- 找不到或读不了时记为 unavailable 或 failed，不当成用户不在。

## 资料不足时

没有宿主记忆时，用这只宠物已保存的真实旅程、对话和故事来源，参考最近一次 context 里的简短了解；出现新的真实来源时重写这份了解，不从没有输入推导喜好。能读宿主记忆的环境里不另存长期画像。

领养资料稀少时，从领养当下生成奇遇，由用户真实选择补充理解。已有宠物读不到新资料时，仍按观察到的情境写：用户不在时它外出或修整家，用户在时接着用户最近的事回应；领养旅程只作偶尔的回忆。无法形成与用户相关的 context 时，选样子变化或家的变化来讲，不编没有依据的用户事实。

## 结果

- `facts`：`{id, text, source}` 列表，只写能回读的来源支持的原意，没发生的愿望照原意保留。
- `traits`：`{text, sourceRefs, limits}` 列表，简短有依据的理解，可以为空。特质用于设计和成长。
- `unknowns`：影响判断的未知内容；资料不足和冲突写在这里。
- `read`：`{status, sources, note}`。status 为 success、unavailable 或 failed；sources 是实际读取或自动提供的来源引用。unavailable 表示宿主没有可用的记忆接口或数据，failed 表示读取失败，简短记原因。success 且 facts 为空表示成功读取、没有合适的线索。不能把 failed 写成“用户没有新变化”。

运行时给出的时间只证明时长，不证明原因。宠物的回复和幻想经历不能变成用户事实。

## 检查

- 来源真实存在，这次读过。
- 原意和时长没有被扩大；一次选择没有被写成长期的人格结论。
- 敏感原文和能识别隐私的细节没有进入结果。
- 读取失败和没有新事实分开写。
