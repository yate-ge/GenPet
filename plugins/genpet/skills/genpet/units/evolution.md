# 单元：evolution · 状态、成长与 memory

输入：context、当前 pet 的 soul、memory、state 三块记录、growth、已经形成的 story。可以带上用户明确的强行成长请求（/genpet-debug）。

## 成长节奏

阶段依次为蛋、幼年、少年、成年，每篇最多前进一阶段。

- **靠经历积累。** 未成年阶段，当前阶段的 memory 经历满五次后，由 Agent 选一次承载成长的故事，尽量对上用户生活中的真实变化；没有新的生活变化时，也可以由已有的共同经历推进，不一直等新资料或截止时间。在此之前继续积累，不设最短天数。每次完成故事后的 memory 重写算一次经历；改措辞和重试不重复计数。
- **最晚兜底。** 蛋在领养后五小时孵化，幼年和少年各一周。到期后的第一次检查必须带来对应的变化；离线期间到了期限时，把这段时间写进内容。五小时是最晚兜底，不是最短等待：未到期但经历已够，也可以承载孵化。未激活的宠物期限暂停，激活的宠物关机期间按实际经过的时间算。
- **成长有预兆和痕迹。** 由基因、memory 和当次 context 形成，能力随成长增强。不展示次数、等级、亲密度或进度条。
- **强行成长。** 用户在 /genpet-debug 里明确要求时，可强行前进一阶段；成年则进入幻化，已在幻化中则结束它、回到原来的样子。这是用户的请求，不能当作用户的生活事实。
- 成长到成年后身体停止成长，memory 始终能继续变。

## 幻化

幻化是成年后一次超越自然的变身：不是按成长轨迹发育，也不是日常样子。

- **对象。** 有一个幻化对象，由 Agent 按这只宠物和这次的契机选：一种超自然的状态、一种能力的显现，或另一种形态都可以。把对象的特点和它自己的身份核心（配色、标志性的器官、眼睛和神情）结合起来。
- **外观。** 要有一眼看得出的大变化，轮廓、构造或质感都和平常不同，又一眼认得出是它变的。目的是趣味和惊喜。仍然可爱、让人愉快；暗色或强烈的形态只是酷，不凶恶、不恐怖。安全边界见 principles.md「形象安全」。
- **契机。** 来自观察：用户连续三天以上保持同一种状态时，由 Agent 判断要不要幻化（读最近几篇故事保存的观察；growth.special.available 为 false 时不进入）。幻化是它自己的、好玩的回应，不评价用户；不把熬夜、加班、情绪或健康写成起因，不暗示用户做得不对。没有这样的契机就不幻化，平常的变化交给日常。
- **节奏。** 只在成年，同一时间只有一个幻化。进入后最多两天，结束后至少隔一周才能再幻化；契机消失时可以提前结束。幻化期间不换日常样子，故事、物件和家照常。
- **结束。** 回到幻化前的日常样子，复用那套图；同一个幻化再出现时可复用。结束后留一点痕迹，例如家里的一件东西或 memory 里的一句。
- 代码里的字段名沿用 `special`。

## memory

memory 是一段短文字，记它对用户的了解、和用户一起经历过的事，以及现在怎样相处。

- 领养时先写出发点；之后故事里有值得记住的事才重写。值得记的有：用户生活里的节点（做完的项目、卡了很久终于解决的问题）、用户对它说过的话、它为这些事给过用户的东西或留在家里的纪念。它自己的物件和第一次做成的事，只在和用户有关时才记。
- 重写时合并或放下旧内容，保留早期的重要相处，保持简短。不写逐次的流水账。
- 提到有图的东西、样子或家时，可以在后面注上图的 ID（例如 art-…），以后能找到那张图。

## 做什么

从故事形成状态和变化。deadline 到期或强行成长时，按 runtime 的要求前进一阶段。成年时判断进入、延续或结束幻化。这次的故事不适合必须发生的变化时，修订故事再形成计划，不能静默跳过。

## 结果

- `stage`：egg、hatchling、juvenile 或 adult。
- `state`：完整的状态描述。
- `reason`：简述故事、context、memory、强行请求或最晚兜底的依据。
- `special`：幻化的描述（含对象和契机），或 null。
- `visibleState`：看得见的改变；无变化为 null。
- `memory`：值得记住时的完整简短重写文本，否则 null。

## 检查

- 阶段顺序、五次经历和截止规则准确；成长来自积累，不评价用户。
- 身体不变的穿戴、状态和姿势属于日常，不算成长。
- 幻化只在成年；有对象，契机是用户的持续状态；没有评价用户。
- soul 没有被修改。
- memory 保留重要的旧相处，引用真实依据，未完成的内容没有写成事实。
- 这里只形成计划，还没有声明显示或成长已完成。
