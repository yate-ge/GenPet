# 单元：encounter · 领养旅程

输入：`context`、`journey`（已保存的背景、各轮场景/选项/用户原话与是否结束，未开始可为空对象）。

## 旅程是什么

领养是用户做选择的一次奇遇，蛋在奇遇里意外得到。背景、场景和选项由可用资料和前面的选择形成，可以遇到其他角色。宠物第一次出现是一颗蛋。

- 一次用户选择算一轮，最多五轮。轮数、情节和结束位置由 Agent 在上限内决定。
- 选项给出看得见的去处或东西，带不同的线索与代价；用户也可以自由回答，同样有效。没有人格评分，没有标准答案。
- 之后兑现选择的后果，让早先的选择继续起作用。
- 未选的选项不能写成用户做过的事；没有明确选择时不替用户回答。
- 每轮保存场景、选项和用户原话，用户离开后从这里续接。只展示选项不算一轮。
- 旅程结束后才设计基因和性格，再画蛋、给领养总结。总结讲旅程、蛋和壳面线索的来由；孵化后的身体留到孵化时发现。

## 结果

在已有旅程上生成当前场景和下一步。未收到用户回答时，保留可回答的场景；收到回答后才记为该轮的选择。

- `text`：当前故事，或结束后的旅程摘要。
- `place`：当前地点，或得到蛋的地点。
- `connection`：用户资料和选择怎样进入旅程。
- `factIds`：引用的实际事实 ID。
- `journey`：`{background, rounds, completed}`；当前待答场景可附在结果中。

保存顺序：先 record-step 保存场景并呈现给用户；收到原话后，再用 `journey-step` 保存该轮（scene、options、userInput、inputRefs），结束时 complete 为 true。最后得到蛋的结果也不透露孵化后的身体。

## 检查

- 场景具体，有线索与代价；前面的选择影响后面。
- 原话有来源，一次选择只算一轮。
- 中断后能从已保存的步骤续接，五轮内结束。
- 没有替用户回答，没有顺手测用户的人格，没有变成找蛋任务。
