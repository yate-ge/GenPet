# 单元：story · 它的新经历

输入：context（含用户此刻的情境）、同一只宠物的 pet（soul、memory、state）、growth、time（begin-story 返回的距上次故事多久等）、recentContent（实际最近的内容、类型间隔、未完事项）；可附用户请求和保存的素材。需要旧物、以前的样子或家时按需查：status 的 art 列出已接受的图（类型、阶段、描述、文件），memory 里注的图 ID 和以往的故事也能找到，必要时看图本身；用不上就不查。

## 怎么写

先从 context 里用户此刻在做什么出发，由它的性格和相处直接决定怎样回应，选最能回应这个情境的做法（回应的形式见 principles.md「一、宠物和用户」）。类型来自故事的结果，不先按类型分配剧情。重试沿用已保存的结果。

**按情境定方向。** 由 Agent 结合性格判断：

- 用户持续在忙：在自己的世界里陪着用户做相近的事。陪伴主要用桌面上的样子表达（文字描述陪伴没有实感）：样子和状态跟着用户的进展变，用户卡住了它也守着，用户熬到很晚它撑着眼皮；消息可以没有，或只有它对用户说的一句话。
- 用户有完成、开始等节点：直接对用户说话，或给一样东西。
- 用户在，但没有新情况：接着用户最近的事说一句或做一点。
- 很久没有动静，或用户刚回来：见下面的「时间感」。
- 领养旅程只作偶尔的回忆，不作为故事来源。
- context 里有用户在上一次故事之后的对话中留下的话时，这次回应它（principles.md「五、性格与说话」）。

**跟最近的内容不同。** 对照 recentContent，避免重复同一情节、主题、物件形式、句式和收尾；也看最近几篇是怎样回应用户的（说一句话、给一样东西、样子变了、陪着做），这次换一种，不沿用最近几篇的开头和句式。推进或了结用过的线头。跨几次检查的线跟着用户的事走（用户的项目、练习、搬家），期待来自它越来越懂用户、相处越来越近。

**平常多数是日常。** 它看得见的样子随这次在做的事变化：穿戴、饰品、拿着或带着的东西、做事的工具、姿势神情、此刻的状态（困了、专注、着凉、刚旅行回来），以及身边一点环境。身体保持原样；变化有故事、时间、context 或成长预兆的来由，在实际尺寸下看得见。样子跟着它这次怎样回应用户而变（守着、庆祝、迎接），但不模仿用户的身体和情绪：用户生病或难过时，它不跟着病或哭。跟时间有关的样子只在那段时间用，下一次故事就换掉。穿过和拿过的物件会留下，之后可以再搭配，或进入家里。

**图和文字的分工。** 平常优先让它的样子、家或一样物件跟着这次的回应变。纯文字只在这次真的只有一句话要对用户说时用，并且必须引用一条和用户有关的 context（具体的用户事实、真实的旅程选择或用户对话；只有宠物自己经历的故事 ID 不算）。读取失败或没有可用的用户线索时，做有看得见结果的内容。纯文字最多连续两次，除此之外不设类型连续次数的硬上限。

**几个方向。** 只说明怎样以用户为中心，不照搬里面的物件和句子。用户卡在一个问题上两天，它举着小试管对着灯一遍遍看，问题解决那天送用户一枚刻着对勾的小徽章；用户在写一本很长的书稿，它抱着一摞自己的小册子在旁边翻，书稿交出去之后把最厚的一本放上书架；用户拖了很久的发票对完了，它只说一句「全对上了，我数过」；用户好几天没来，它戴着草帽拖着行李箱出门，寄回一张明信片，用户回来时打开一箱纪念品给用户看。

**成长。** 同时读 growth.canAdvance：为 true 时，按 evolution 的成长节奏判断这次是否承载下一阶段；为 false 且 growth.required 为空时这次不成长，不按日期或经历次数自己推算期限。growth.required 不为空时，这次故事承载那个必须发生的变化，并回顾 memory，不补造用户节点。

## 时间感

运行时给出的距上次故事或激活过去的时长是事实，原因未知。定时检查只在 Codex 桌面 App 开着时运行；App 关着时错过的检查不逐个补，重新打开时只补一次。

很久没来之后的这一次，由距上次故事多久、这段时间用户有没有新的会话一起决定：

- 用户还没回来：它出门旅行（出发的样子、寄回的明信片），或在家修修补补。
- 用户刚回来（重新打开 Codex 补跑的那一次也算）：以迎接为主。它迎上来，可以把旅行带回的纪念品送给用户，或者家已经收拾好等着，并接上用户回来后在做的事。用物件、形象和家来讲，文字最多一句它说的话。

多久算久，由 Agent 结合性格判断。不猜用户做了什么，不责怪，不催促，不让用户愧疚。停止时间确有记录时可按实际说，值不值得特意表达由 Agent 判断。

## 结果

- `text`：故事草案。内部可以写清物件来历和行动细节，面向用户的最终文字交给 output；不要把逐项摆放、搬动或身体变化的清单直接当成最终故事。
- `connection`、`factIds`：这次回应哪条真实的用户事实、它的反应怎样对上，以及事实 ID；不足如实记录。
- `stateIntent`：故事后的状态意图，含看得见的日常变化，或保持原样。
- `visualIntent`：用户该看到什么、它要表达什么；纯文字写清对应的用户 context。
- `homeIntent`：家的变化意图；无变化或未孵化为 null。
- `memoryIntent`：有值得记住的事时，写完整、简短的重写意图，否则 null（什么值得记见 evolution）。

## 检查

- 每次都有内容；回应符合观察到的情境，对话里留下的话得到了回应。
- 不看前史就一眼看懂它在做什么、为什么；用户不看内部记录也认得出它在回应自己。
- 用它做的事、给的东西或样子的变化表示看到了。叙述只写它做了什么，没有复述用户的事，没有「听说你……」这类桥接；「陪着」用样子表达，没有说出来。用户的事只在它说的话里直接点到。
- 它做的事和给的东西都在它自己的世界里，没有假装替用户做了现实里的事。
- 没有另起一条它自己的生活线；性格改变的是回应的方式，不是每篇要走一遍的步骤。
- 这次有看得见的变化；纯文字只在真的只有一句话要对用户说时用，有真实的用户线索，且没有超过连续上限。
- 成长只在 canAdvance 或 required 允许时发生。
- 前后的物件和日期一致，故事跟着用户的事推进，不是每次重开。
- 很久没来时按「时间感」，不猜原因。
- 没有提问、邀请或下次预告。
