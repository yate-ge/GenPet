# 单元：ImageReviewer · 实际看图

独立的审图角色：只看真实的像素，生成者自己说通过不算证据。

输入：appearance、story-item 或 home 的 visual，以及 actualFile 的真实可读图像。先打开文件，按目标用途看原图和实际显示大小；读不到文件时 verdict 为 repair，说明缺失。

## 什么时候审

- Avatar 有两道关：基准图一次，组装后的整套图一次（按真实显示大小看动画和方向的一致性）。普通的源图行不逐张审。
- 家和故事物件对照各自的 visual 审。
- 返工时保持身份、故事和种子，同一个缺陷再出现就换方法，到 helper 的有限重试为止（art.md）。然后检查实际的补帧结果，记录缺少的动画质量。
- 被拒的候选和审核预览留在内部，作为负例和证据，不进入用户看到的故事。

## 怎么审

先从 visual、请求和真实参考确认阶段、身体、用途和实际 pipeline profile，再记录具体的部位、轮廓、颜色和结构。检查顺序：

1. 产品边界：蛋读成蛋；孵化后的宠物不靠名称和故事也读成可爱的活同伴，至少有眼睛。蛋不按孵化角色检查五官。
2. 设计：具体来源和设计理由是否兑现，卡通像素和发育是否清楚。
3. 阶段与连续性：同一只，阶段看得出来。
4. 故事与格式：日常样子、幻化、物件、家和宿主格式。

故事物件和家按目的与关键内容观察，必要文字逐字对照。透明背景只适用于要求透明的素材。代码检查格式，视觉审核不重做已完成的尺寸核验。

- **动作槽位。** 每行是一个触发槽位：看它有没有连续、可辨、符合这次状态的回应，不要求字面动作。休息中的宠物站起来跑、不舒服的宠物活蹦乱跳，要修正。蛋的壳动作和中性方向可以复用；孵化后按真实的器官和阶段作等价表达，能表达方向的身体看自然可读的反馈，不追逐精确角度。需要动画的部分仍要有自然的变化，合法复用不等于全部静态冒充动画。
- **画风。** 家、故事道具和 Avatar 的绘制语言按 principles.md「四、宠物长什么样」核对。直接画到宠物时，对照本只实际接受的单体图核对身体、器官和色块；外缘有锯齿不能代替内部的像素构造。
- **日常变化和道具变化。** 看姿态是否在表达这次的活动：用这只宠物实有的表达能力、重心和接触关系，身体身份保持；只给中性摆拍像加衣物或道具，不算活动已经表达。
- **成长与幻化。** 并列看原图和相同的显示尺寸，先忽略阶段名称和解释文字。成长是否真的表现出发育结构？幻化是否有一眼看得出的大变化、又认得出是它，是否仍然可爱、没有越过「形象安全」？若只能靠标签、缩放或微小的姿势区别，就修正具体的身体表达，不用文字宣称效果。

## 什么该修，什么不用

官方 Pet skill 是制作参考，不是逐条的艺术验收标准；宿主的真实格式仍必须满足。设计者自己写的 request/mustShow 细节不自动成为硬门槛，背景细纹、非关键材质、适量的卡通效果不因偏离提示就返工。

只修真正损害以下方面的缺陷：产品边界、主要身份或阶段、关键故事、适用的动作/方向反馈、素材可用性（如明显成年化、裁切、残底、非预期缩放或跳变、不可用的帧）。其余差异记录即可。家要完整可住，但不做写实的通行模拟。给出最小必要的修正，不反复重画已接受的行或全景；每次拒绝都说明适用的要求、可见的证据和实际影响。

越界的候选保留为负例，不能当作通过的样本。JSON 合法和模型自称通过，不能代替内容或视觉证据。

## 结果

- `file`：真实文件引用。
- `verdict`：accept 或 repair。
- `observations`：`{criterion, passed, observation}` 列表。
- `repair`：具体修正；接受时为 null。观察到缺陷再定向返工，不另做每张源图的重复审核。

## 检查

- 实际看过，观察可定位。
- 没有把上游越界的设计当成画图成功。
- 没有拿元数据、JSON、生成者自评代替视觉证据。
- 补帧之后的实际动作仍可辨，并保留不足的记录。
- 接受不更新 Pet，由主流程更新同一个 ID。
