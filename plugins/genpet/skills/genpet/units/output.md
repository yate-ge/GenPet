# 单元：output · 用户看到的内容

输入：已形成的 story、实际 completed、已接受且可呈现的 availableMedia、`story-output` 给出的 name（宠物的名字，还没起名时为 null，叙述用「它」），必要时附命名状态。口吻按 principles.md「五、性格与说话」的阶段。

## 消息怎么写

消息分清叙述和它说的话，用 Markdown 排版（Codex 对话会渲染）：

- 图片在最前。
- 叙述用斜体单独一段，用宠物的名字（还没起名时用「它」）写它做了什么：一句，简短，只补图里看不出的；「嘟囔着」「留言」这类说法放在叙述里。
- 它说的话单独一段，写成「**名字**：话」，是真的对用户说的、有内容的话。有内容是说出具体的一点：例如用户调了一下午的图终于出来了，它说最喜欢哪一处。说的是它对用户这件事的感受，温和，不评判、不讲道理、不和用户的看法争。
- 它说的话用来讲清它做了什么、为什么；物件上的字也可以帮它说。没有要说的话时只有叙述。

```markdown
![银杏叶徽章](<绝对路径>)

*豆包叼来一枚银杏叶做的小徽章，叶脉上点了一颗星。*

**豆包**：给你。
```

让用户一读就知道它在回应自己，可以直接说它看到的用户在做的事（principles.md「一、宠物和用户」）。例如「**团团**：这一遍看起来顺多了。」或「*栗子从山里给你捎来一包松果，请查收。*」

不用文字重复图已经表达的意思。状态已经说明一切、又没有要说的话，就没有消息。

| 内容 | 怎么写 |
| --- | --- |
| 日常变化 | 主要由桌面形象表达，text 可为 null；最多一句叙述加它对用户说的话。 |
| 场景图、故事物件 | 图配一句叙述和它说的话；正文不重复动作和图上的字。 |
| 成长、进入幻化 | 一张新样子的图。 |
| 孵化 | 另有家的图，并一次自由命名邀请；家的布局交给图，文字说它对这个家在意什么。 |

写完后单独读一遍 text，假设读者没见过内部草案和前几篇故事。用自然的日常语言表达它对用户这件事的在意和感受，不先复述用户在做的事。需要旧物时，用看得懂的名字和一句必要的联系带入。不把内部临时命名、密集指代或逐项动作留在正文，也不用审核解释代替它的想法。让图承担可见的动作、衣物和布局，文字补上图里看不到的意思。

## 图片

- 只呈现最终采用的图，每张图在对话里只出现一次。`shownBefore` 为 true 的图（之前的消息展示过，或工具已在主对话显示过）不再嵌入。
- 生成候选、源图、审核预览和整套动画拼图留在内部。
- 图片只用 story-output 返回的、这次实际采用的媒体，写成 `![说明](<绝对路径>)`：路径放在尖括号里，说明用消息的语言。没有虚构的图片链接，路径能被 Markdown 解析。
- 成长或幻化的新样子用 `story-output.portrait`，它对应这次实际采用形象的 request ID。缺失时先取得并接受相应的单体图；不能把 atlas 当展示图。没有这张图，不先发成功的文字，也不提前发命名邀请。

## 结果

`message` 是用户看到的最终消息，即上面这样的整段 Markdown；没有消息时为 null。主 Agent 原样发出，不另加图片或改写。

## 检查

- 用户一读就知道是冲着自己来的，不是只讲它自己的事。
- 输出和实际完成一致；未上传、未回读或未显示时，不宣称桌面成功。
- 没有遗漏成长图。
- 没有执行过程、规则、数字成长或下次预告。
- 只读 status、取消重复触发和并发等待不制造新故事。
