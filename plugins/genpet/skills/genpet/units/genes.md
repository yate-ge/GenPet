# 单元：genes · 具体的宠物设计

输入：同一份 `context`、已结束的 `encounter`、`random`（工具返回的来源类型、种子、候选和选中 ID）。用户特质和旅程是设计依据。

## 设计方法

每次新基因这样形成：具体熟悉的来源 → 设计理由 → 身体、属性、能力及特殊结构。

- 来源写到具体的物种或品种、具体的传说，或具名作品里的具体角色；只用确知的设定，不了解的部分保留未知。人类熟悉的来源不等于用户喜欢。
- 工具在后台给出来源类型和种子：自然动物和植物较多，日常物件转成的生命较少，传说、神话、作品和其他幻想生命更少。概率和选择结果不向用户展示。
- 在工具给出的来源类型内，先形成几个差别明显、各有理由的候选，用保存的种子选出一个。候选和选择作为中间结果保留，重试沿用，不换。
- 设计理由具体说明来源、旅程和用户线索的联系，各主要特征怎样形成、为什么适合。属性、能力和特殊结构各有用途和来由；只加一个部件或换色不算设计。随机性用来探索有依据的不同诠释，新奇本身不是理由。
- 身体基因和性格彼此有关，各自表达完整。
- 内容具体、有趣、可爱，能在小尺寸下转成清楚的身体。幼年没有成熟结构。蛋只体现壳面线索。

## 结果

- `designReason`：具体来源；为什么适合用户特质和旅程；如何转成各主要特征、能力和独特结构。
- `genes`：自包含的开放文本，写身体构成、属性、能力、结构和它们的理由，以及从幼年到成年怎样展开。带上设计理由，使后续只读 genes 也能理解。
- `eggAppearance`：完整常规蛋壳上的颜色、纹理和斑纹线索。

## 检查

- 身体和性格能回到真实的选择和特质。
- 主要特征是一起设计出来的，不是拼完再补一个来源名。
- 已保存的 genes 原样沿用；图片失败不重抽。
