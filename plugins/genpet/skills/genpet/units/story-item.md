# 单元：story-item · 故事物件

输入：context、pet、已形成的 story、savedArt。

## 做什么

判断这篇故事的图是不是场景图或关键物件，以及怎样按它自己的形式表达。图画的是故事要传达的东西：道具叙事就画物件，物件是一看就懂用途的东西，例如奖章、明信片、装满纪念品的行李箱；场景图画宠物在某个场景里做某件事，例如在小桌前整理谱页。形式由故事决定，不设物件目录。

- 按目的、视角、形式惯例和必须出现的特征设计。道具叙事里物件本身是主角；场景图里是宠物在做这件事。
- 带文字时写原文和语言，先保证自然可读；图上的文字和正文各有作用，不重复。
- 已有合适的物件图直接复用。
- 绘制语言见 principles.md「四、宠物长什么样」。若图中出现宠物，另附本只实际接受的单体身份参照，保留身体、色块和器官。
- 样子变了由 appearance 画，家变了由 home 画，这里不重复生成。

## 结果

- `reason`：这篇故事为什么需要这个物件或场景，或本次由样子或家的变化承担这张图。
- `items`：这次物件的变化（给了用户、带回来、放进家里、拿走或收起），写法见 host.md「StoryPlan」。没有变化可以省略。
- `item`：null，或 `{medium, purpose, viewpoint, form, mustShow, text?, visuals}`。medium 开放（物件、场景等）；form 写清画幅、边框、背景；visuals 含实际请求和参考，复用项指向 artId/file。

item 为 null 时，这篇故事的图是形象或家的变化；story-item、appearance、home 三者都没有图就不成立，因为每个故事都要有一张图。

## 检查

- 不靠说明就看得出是什么、为什么给或带回来。
- 形式与用途相合，必要特征落实到请求里。
- 已有物件改去向时用它的 `id`，不重复添加；清单看 status 的 `items`。
- 物件的故事与用户的真实资料相连，体现它在想什么。
- 物件和场景都在它自己的世界里，给用户的是虚拟物品，不冒充用户现实里的东西；没有虚构用户收到、使用或感受。
