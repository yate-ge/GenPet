# 单元：story-item · 故事物件

输入：context、pet、已形成的 story、savedArt。

## 做什么

判断这篇故事有没有值得画的关键物件，以及怎样按物件自己的形式表达它。图画的是故事要传达的东西：故事物件就画物件，不做普通场景插图。物件是一看就懂用途的东西，例如奖章、明信片、装满纪念品的行李箱；形式由故事决定，不设物件目录。

- 按目的、视角、形式惯例和必须出现的特征设计。物件本身是主角。
- 带文字时写原文和语言，先保证自然可读；图上的文字和正文各有作用，不重复。
- 已有合适的物件图直接复用。
- 绘制语言见 principles.md「四、宠物长什么样」。若图中出现宠物，另附本只实际接受的单体身份参照，保留身体、色块和器官。
- 宠物和家各有自己的单元（appearance、home），这里不重复生成。

## 结果

- `reason`：这篇故事为什么需要这个物件，或本次无物件。
- `item`：null，或 `{medium, purpose, viewpoint, form, mustShow, text?, visuals}`。medium 开放；form 写清画幅、边框、背景；visuals 含实际请求和参考，复用项指向 artId/file。

item 为 null 不表示纯文字：这篇故事仍可有形象或家的变化；是否纯文字由全部结果判断。

## 检查

- 不靠说明就看得出是什么、为什么给或带回来。
- 形式与用途相合，必要特征落实到请求里。
- 物件的故事与用户的真实资料相连，体现它在想什么。
- 物件是它世界里的东西，给用户的是虚拟物品，不冒充用户现实里的东西；没有虚构用户收到、使用或感受。
