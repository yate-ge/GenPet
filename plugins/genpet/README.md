# GenPet for Codex

GenPet is one native Codex Pet that begins as an unknown egg, hatches after five real hours, and grows each day. Its pixel artwork is generated by Codex imagegen and assembled with the bundled Hatch Pet pipeline. This archive contains the plugin runtime and generation tools; it contains no ready-made user Pet or research example artwork.

## Install from the release ZIP

Requires Node.js 22+ and a Codex Desktop build with custom Pets and plugin support.

### Ask a Codex Agent

Open the extracted release directory as a Codex project, then send this message:

> 请安装当前目录里的 GenPet Codex 插件。确认这里有 `.agents/plugins/marketplace.json` 和 `genpet/README.md`。检查 Node.js 22+ 和 Codex CLI；在 `genpet/` 执行 `npm ci --omit=dev --ignore-scripts`，然后把当前解压目录作为本地 marketplace 注册，并安装 `genpet@genpet-local`。若已有 GenPet 插件，先检查它的 marketplace 来源，只更新同一个安装，不创建重复插件。安装后在新 Codex 会话检查 GenPet 技能与 MCP 工具是否加载，报告路径、版本与检查结果。不要重置、加龄或重新领养现有宠物；保留 `~/.genpet/` 和 `~/.codex/pets/genpet-companion/`，不要为了测试安装而生成新图像。

Installing the plugin does not adopt a Pet or create a scheduled growth task. [Official OpenAI plugin packaging guidance](https://developers.openai.com/plugins/build/plugins) explains local marketplace registration. If the Agent cannot verify loading without a new task, it must report that limit.

### Install manually

1. Unzip `genpet-0.1.0.zip` into a persistent directory. The extracted directory contains `.agents/plugins/marketplace.json` beside `genpet/`.
2. In `genpet/`, run `npm ci --omit=dev --ignore-scripts` to install the locked production dependencies.
3. Run `codex plugin marketplace add /absolute/path/to/extracted-directory`, then `codex plugin add genpet@genpet-local`.
4. Start a new Codex task and ask: **领养、安装并启用我的 GenPet 自动成长**. The skill generates your own egg and installs one `genpet-companion` entry. Select it once in Codex Pets.

The `/` menu exposes `genpet-reset`, `genpet-grow`, and `genpet-state` skills for explicit debugging; their parameters are in [debug commands](docs/DEBUG_COMMANDS.zh-CN.md). Reset starts a new adoption clock, while grow keeps the existing identity and changes only logical debug age. The scheduled growth task never calls these debug commands.

Generation requires a Codex run; the local Node server cannot call imagegen alone. Automatic display refresh requires a live local Codex debugging channel. The plugin confirms the floating Pet's displayed sprite hash before reporting `displayStatus=confirmed`; file installation alone is not visual confirmation. See [native refresh behavior](docs/NATIVE_REFRESH.zh-CN.md).

Local Pet state and generated artwork live in `~/.genpet/`; the native entry lives at `~/.codex/pets/genpet-companion/`. They are not stored inside this plugin directory.
