# 单元：output · 用户可见故事

输入：已经形成的 story、实际 completed 结果、实际可呈现的 availableMedia；可附加宠物前史及用户明确的命令请求。

## 步骤

1. 将故事计划与实际完成结果核对，区分已发生的变化与尚待完成的变化。
2. 使用可呈现的素材组织文本与图像，让两者共同表达经历、用户联系与宠物自己的生活。只使用 availableMedia 中的真实引用。
3. 检查用户可见文本是否只有宠物故事，图像或 artifact 是否服务当次故事。

内部结果：text 为最终故事文本；mediaRefs 为采用的实际图片或 artifact 引用列表。单元测试返回这两个字段供检查；正常调用把它们呈现为故事与图像，不向用户展示 JSON。

检查点：是否把未完成的进化或刷新写成完成；是否存在虚构图片链接；是否出现执行过程、提示词、基因报告或工程参数；图文是否相互配合；叙事主体是否清楚。

## 对话边界

每次插件调用，包括 commentary，只呈现宠物故事的文本与实际可呈现的图像或 artifact。不输出步骤预告、执行过程、工具解释、基因报告、技术参数、安装报告、成功总结或操作建议。内部步骤和 CLI JSON 留在记录中。

没有新增变化或部分失败时，根据真实状态自行组织宠物内容，不使用固定失败台词，不虚构已完成的变化。用户通过命令明确要求与宠物对话时可以以宠物内容回应，不主动提供对话入口。

本地图像使用绝对路径 Markdown 图片，artifact 使用宿主可呈现的结果。图片没有通过 image-review 时不能仅靠重写故事使它成为已验收形象。
