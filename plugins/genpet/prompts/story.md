# 单元：story · 新经历

输入：context 的结果、同一个体的 pet 记录（含已保存的 personality）；可附加近期故事、保存素材与用户请求。共同规则见 meta.md「用户联系」「故事与状态」「个体性格」，变化判断由 evolution 单元完成。

## 步骤

1. 读取性格与近期故事，选择这次主要是独立生活、共同经历还是用户事件引发的状态变化。不机械轮换；资料不足时仍可延续自己的生活。
2. 从性格选择行动，让读者通过行为看到这个个体怎么相处。共同经历或状态变化在正文中写清实际用户线索与宠物的回应；不要只有题材相似或内部联系说明。使用用户已给出的名字，未命名时用描述称呼。
3. 先写故事草案，再说明状态意图、性格具体如何影响行动，以及图文各自要表达的内容。此时没有执行变化，草案不是完成声明。
4. 标明采用的事实 ID。独立生活在 connection 中如实说明本次没有新增用户关联；状态意图使用当前保存状态，不触发身份形象或阶段变化。题材、视角、篇幅和形式保持开放。

结果：text 为新故事草案；connection 如实说明本次用户联系或其缺少；evidenceIds 引用 context 的事实；personalityExpression 简述性格已经怎样落实为正文中的行动；stateIntent 为故事带来的状态意图；visualIntent 说明图像或 artifact 如何配合文本。内容开放，不需要故事分类标签。

检查点：故事是否先于状态决定；是否延续前史又能形成新经历；共同经历是否在正文中发生；性格是否影响行为而非只出现标签；状态变化是否有用户原因；宠物的生活是否只是复述用户工作。资料不足时不补造事实。

## 后续流程

保存本单元结果 → evolution 判断阶段、状态和特殊变化 → appearance 决定复用或新视觉方案 → 保存 StoryPlan → 制作实际素材并运行 image-review → 更新目标 Avatar → 完成故事 → output。

StoryPlan 的 text 使用本故事；basis 摘要记录用户联系、性格与 evolution 的判断；stage、state 由 evolution 提供；appearance 来自 appearance 单元。事实引用与性格行动保留在单元记录中，不额外建立一套分类与校验机制。没有形象变化时省略 appearance，仍可以表达故事图像。一次故事不必进化，也不必生成新形象。

中断时继续已保存的结果和计划。各步的内部记录使用 record-step；对话只呈现实际结果支持的故事和图像。
