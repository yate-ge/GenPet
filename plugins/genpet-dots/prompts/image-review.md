# 单元：image-review · 实际图像检查

输入：appearance 单元中的一个 visual 方案，以及 `actualFile` 对应的实际图像。判断来自实际查看该文件，原图与宿主实际显示尺寸各看一次；没有可读图像时 verdict 为 repair，并说明文件缺失。

## 检查

按 meta.md「检查顺序」逐项观察：

1. **产品边界**：描绘蛋或宠物时对照「字面蛋」「孵化后的生命」。不画宠物的故事场景或 artifact 按其实际内容检查。
2. **设计表达**：对照 visual 中的来源与故事依据，指出哪些可见特征体现灵感及其转化。“依据是否成立”与“视觉是否兑现”分开记录；方案本身越界或缺少依据记为上游偏差。
3. **视觉语言与阶段**：对照「视觉语言」「阶段表达」。
4. **连续性、状态、故事联系与宿主格式**：分别观察。透明背景等要求只用于 Avatar 素材；蛋形相近、宠物之间相似不记为偏差。

每项写具体可见观察：哪个部位、什么形状、颜色或姿态，不用“图像一致”之类的总评。图像本身不能证明用户感到联系。

## 结果

`file` 为实际文件引用；`verdict` 为 accept 或 repair；`observations` 为 `{criterion, passed, observation}` 列表；`repair` 在需要修正时描述具体视觉修正，接受时为 null。检查项由当前个体与请求决定。

## 修正

修正沿用同一份 genes、故事计划和有效参考，只重做有偏差的图像；原候选与越界候选保留为负例。用户否决的版本不作为接受。本单元不更新 Avatar，也不通过重新领养修复图像。生成者自己的判断仍需独立检查或用户评价核对。
